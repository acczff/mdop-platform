# ADR-0002：财务通过只读契约引用收发事实

- 状态：候选，随 R3 金额依据 PR 审核
- 日期：2026-10-12

## 背景

R1/R2 已建立采购、销售、生产和 WMS 数量履约。R3 需要人工金额依据及异人确认往来；数量履约不能自动视作金额确认，财务也不能创建第二套数量账。当前部署仍是同进程、同库的模块化单体。

## 备选方案

1. 在采购/销售模块各自维护金额和往来：模块数量较少，但会重复财务初始化、复核、余额与幂等规则，后续核销难以保持一致。
2. 财务直接读写各业务表：初期代码较短，但会绕开数量业务的来源映射及执行核对，表结构和写入职责相互耦合。
3. 独立财务模块，通过公共只读契约读取采购/销售认可的事实：保留统一金额规则，业务模块继续解释自身来源。

## 决策及理由

选择方案 3。新增 `mdop-finance`，只持有演示初始化、金额依据、往来、财务审计和命令记录。`mdop-common` 定义 `FinanceSourcePort`；采购/销售提供适配实现，继续通过已有 WMS 契约读取已合格上架或实际出库事实。Boot 负责装配，财务不依赖采购/销售的实现包，不写 WMS 表。

来源保存订单、行、收发事实及往来方/物料快照。金额提交和复核时重新核对；同一事实只能有一份有效正向依据。初版单组织财务写入锁定基线行，以本地事务保持状态、往来、审计与幂等结果一致。来源已完成后，现有业务不允许普通撤销实物事实；后续反向业务须保留原金额并建立独立调整。

## 代价与重新评估条件

- 增加一个 Maven 模块及两份来源适配器，需要在业务来源变化时维护契约与集成回归。
- 单组织串行写入限制并发，适合当前演示切片；出现经测量的吞吐瓶颈或多组织需求时再评估锁粒度，不预建分布式锁平台。
- 该契约依赖同库读取，不承诺远程一致性；拆库或接入真实外部系统前，重新设计来源版本、撤回协调与可靠消息协议。
- 当前只有正向往来；新增退货、收付款、核销、成本或期间控制时必须扩展验收，不能用普通删除覆盖已确认金额。

业务口径及验证入口见[金额依据与往来确认](../erp/金额依据与往来确认实现与验收.md)。本决策不授权部署，也不规定具体工厂的会计政策。
