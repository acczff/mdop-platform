## 目录原则

1. **先功能、后分层**：复杂模块先按子域分目录（如 `receiving`、`inventory`），子域内部再分 `api/application/domain/infrastructure`。
2. **简单 CRUD 不强制四层**：主数据、字典类模块保留“接口 + 应用 + 仓储”即可，避免空层。
3. **一个文件一个公开类型**；请求/响应模型可集中在一个 `*Models` 文件，按用例分组。
4. **SQL 只在 `infrastructure`**；应用层通过仓储接口取数。
5. **测试镜像包结构**：`src/test` 的包名与被测代码一致，便于定位。

## 数据访问约定

| 约定 | 说明 |
|---|---|
| 仓储接口放 `domain` | 只表达“需要什么”，不出现表名与 SQL |
| 实现放 `infrastructure` | 显式列名、参数绑定、统一分页 |
| 复杂查询用查询对象 | 一个查询一个类，条件对象 + 显式列 + 行映射 |
| 禁止 `SELECT *` | 新增代码不写；存量逐步替换 |
| 分页统一 | 深分页改键集分页，偏移量设上限 |
| SQL 变更附执行计划 | 新增或修改核心查询时说明走哪个索引 |

## 测试约定

- 业务规则优先写**不依赖数据库**的测试；跨模块与事务行为写集成测试。
- 修 bug 先写失败用例，再修复。
- 涉及库存、金额、权限的改动，必须覆盖异常与并发分支。
- 提交前至少运行受影响模块的测试，合并前运行全量 `verify`。
