# 跨仓调拨分批收货

> 交付更新（2026-10-07）：相关实现已进入 main，WMS 公共流程已完成有限验收，见 [当前验收与合并记录](../project/WMS公共流程验收清单.md)。本文各次测试数量、迁移数量及环境记录保留其当时含义，不代表当前总量或生产部署状态。

## 业务范围

承接跨仓调拨及库存冻结首版。申请、异人审批预占和源仓发出仍按整单执行；目标仓可以分多次登记实际收到的合格数量，每次独立记账。首版仍限定一个库存批次和一个目标库位，不含分批发出、运输损失、差异核销、在途过期处置或调拨冲正。

- 每次明确填写本次实收数量，最多六位小数，必须大于零且不超过剩余在途量。页面不会默认填入全部余量。
- 发出后剩余在途量为 `调拨数量 - 累计实收数量`。每次收货只增加本次目标库存，不再扣源库存。
- 未收齐时单据保持 `IN_TRANSIT`；已发生实收的页面状态显示“部分收货（在途）”。收齐后变为 `RECEIVED`，单据的 `received_by/received_at` 记录最后一笔收货完成信息，各次操作人和时间由收货记录追溯。
- 分批期间不能取消或再次发出。每次收货重新校验目标仓启用状态、库位、仓库用途和有效期；源仓发出后停用不妨碍目标仓正常收货。异常部分保留在途，不自动核销。
- 目标库存冻结时允许归并入库，但可用量保持零；库存原有冻结审计不覆盖。
- 两仓按编号顺序加锁，单据累计数、收货记录、操作记录及库存流水在同一事务提交。并发请求不能超收，同一幂等请求不会重复入账。

## 接口、权限和追溯

新增 `POST /api/v1/wms/cross-transfers/{id}/receipts`，请求包含 `idempotencyKey`、`quantity`、`reason`。使用既有 `wms:cross-transfer:receive` 功能权限和目标仓数据权限；不要求接收人具有源仓数据权限。幂等摘要绑定单据、操作人、本次数量和原因，`2` 与 `2.000000` 视为相同数量。

列表、详情增加字符串形式的 `received_qty`，`in_transit_qty` 返回真实剩余量。操作历史增加 `receipt_id`、`quantity`、`cumulative_qty`、`remaining_qty`；库存流水增加 `cross_transfer_receipt_id`，页面显示 WT 调拨编号与 CR 收货编号。

原 `/receive` 接口保留，用于尚未分批的整单收货及历史原请求重试。已经部分收货时，新的旧式整批请求被拒绝，必须通过新接口明确提交本次数量。旧请求重试保留原摘要规则；新旧接口共用操作幂等键空间，不能利用换接口重复记账。

## 迁移与对账

新增 `V202610070012__partial_transfer_receiving.sql`：

1. 调拨单增加累计实收量及状态约束，历史已收货单回填全量实收。
2. 新建逐笔收货表，保存本次、累计和剩余数量，关联原操作记录及目标库存；历史整批收货回填为一笔 CR 记录。
3. 允许同单多次 RECEIVE 操作和多条 CROSS_IN 流水；保留每单一次 CROSS_OUT、其他动作一次及每笔收货一条入库流水的唯一约束。
4. 原调拨单、操作记录、幂等键、摘要、库存数量及实物流水编号保持不变，仅为历史入库流水补充 CR 关联。
