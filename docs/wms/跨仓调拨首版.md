# 跨仓调拨首版

本页记录首版整批收货范围与验收。后续[分批收货迭代](跨仓调拨分批收货.md)已增加逐笔实收、累计/剩余在途量和 CR 收货追溯；部署与当前接口以迭代文档为准，历史验收记录保留。

一张 WT 调拨单只包含一个库存批次和一个目标存储库位，数量最多六位小数。流程为申请 → 另一人审批并预占 → 源仓实际发出 → 目标仓整批收货。待审批可驳回或取消，审批后发出前可取消并释放预占；发出后不允许取消。不包含部分收货、运输损耗、差异处理、调拨冲正或外部系统接口。

## 库存规则

- 仅同用途的原料仓之间或成品仓之间调拨，排除线边仓；两仓必须不同，申请、审批和发出时均须启用。
- 源库存须为企业自有、合格、未过期、正式存储区库存，且没有生产分配；审批时重新校验可用数量。申请不占用库存。
- 审批增加预占、减少可用数量，保留预占事件并递增预占版本，旧盘点快照因此失效。
- 发出时扣减源仓在手与预占，记录 CROSS_OUT；单据在途数量等于申请数量，目标仓不提前产生可用库存。
- 整批收货时记录 CROSS_IN，增加目标仓在手与可用数量，在途归零。物料、来源、供应商、批次、日期、质量和货权维度保持不变。
- 在途到期或目标仓停用时拒绝普通收货，保留在途记录等待后续异常处理，不能通过本功能绕过有效期或更改单据数量。源仓发出后停用不阻止目标仓正常收货。
- 对账同时核验两端流水和在途数量；在手变动合计 + 在途 = 0，不把运输途中货物算为仓库可用库存。

## 权限与可靠性

功能权限为 `wms:cross-transfer:read/create/review/ship/receive/cancel`，另需 `wms:warehouse:{id}` 数据权限。申请者需两仓权限，审批、发出、取消需源仓权限，收货需目标仓权限，查看需任一参与仓权限。管理员也不能审批本人申请。现有操作账号不自动增加权限。

页面账号还需 `warehouse:read` 以选择仓库；申请账号需 `wms:inventory:read` 以选择源库存。目标仓收货人可以只拥有目标仓数据权限，无须同时获得源仓全部库存的查询权限。

每次写操作都携带幂等键，绑定单据、动作、操作者和完整请求；超时后以原请求重试。同键不同请求返回冲突。两仓按 ID 顺序加锁，单据、库存、预占和操作记录在同一事务提交。所有原有库存流水保留。

## 接口和验收

`/api/v1/wms/cross-transfers` 提供分页列表、申请、详情、操作历史，以及 `/{id}/approve|reject|cancel|ship|receive`。前端“跨仓调拨”支持选择源库存、目标库位、数量和原因，再按角色完成动作。

验收覆盖：双人审批、预占释放、六位小数守恒、在途隔离、整批收货、重复请求、权限与跨用途限制、并发抢占、事务回滚和预占变更使旧盘点失效。异常请求与列表加载失败不能保留可操作的旧数据。数据库验证只在测试容器及隔离验收环境执行。

升级通过新增迁移 `V202610070010__cross_warehouse_transfer.sql` 创建调拨单与操作表、扩展预占和库存流水外键及约束；不改写旧迁移。部署时先备份并停止旧版本写入，按依赖 PR 顺序升级；升级后执行 `scripts/audit-inventory.sql`，所有差异数必须为零。已有调拨数据时不得直接删表回退，应使用验证过的备份恢复方案。
