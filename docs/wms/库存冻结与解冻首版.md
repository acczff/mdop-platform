# 库存冻结与解冻首版

> 交付更新（2026-10-07）：相关实现已进入 main，WMS 公共流程已完成有限验收，见 [当前验收与合并记录](../project/WMS公共流程验收清单.md)。本文各次测试数量、迁移数量及环境记录保留其当时含义，不代表当前总量或生产部署状态。

## 范围与规则

页面 `/freezes` 提供按仓库分页查询、整条库存冻结、另一人审批解冻及审计详情。库存查询页显示当前冻结编号并提供管理入口。首版不处理部分数量冻结、线边库存或生产占用库存。

- 冻结立即生效，原因必填；在手数量不变、可用量归零，原有预占保留。只允许冻结在手量大于零且尚未冻结的库存。
- 冻结独立于质量状态和库存维度。待检、合格、不合格库存均可冻结，解冻不会把待检或不合格品变成可用品。
- 冻结后禁止新的预占，以及已预占业务的发料、销售拣货/复核/发出、调拨审批/发出。仓内移出、质检转出、上架转出、采购退货和冲正扣回也检查冻结状态。
- 允许取消已有预占，减少预占量但可用量仍为零；允许入库归并，增加在手量但整条记录继续冻结。冻结只针对选中的库存维度，不自动冻结其他库位的同批次。
- 解冻由另一名具有审批权限的操作人填写原因并直接批准，不另建解冻申请单。管理员也不能审批本人冻结。只解除当前冻结编号；历史解冻请求重放不能解除后续新冻结。
- 解冻时按当前在手、预占、生产占用和质量/库位计算可用量，不直接还原旧快照。合格正式存储库存可用量为 `在手 - 预占 - 生产占用`，其他情况仍为零。
- 冻结和解冻递增库存预占版本，旧盘点单即使账面数量恢复原值也需重新盘点。

## 权限、接口与数据

权限为 `wms:freeze:read/create/review`，另需 `wms:warehouse:{id}` 仓库范围；页面仓库选择需要 `warehouse:read`，创建时读取库存需要 `wms:inventory:read`。现有业务账号不自动扩权。

接口：`GET /api/v1/wms/freezes?warehouseId=...`、`GET /api/v1/wms/freezes/{id}`、`POST /api/v1/wms/freezes`、`POST /api/v1/wms/freezes/{id}/release`。写入提供幂等键、必填原因；冻结另传 `balanceId`。幂等摘要绑定库存/冻结编号、操作人和原因。

迁移 `V202610070011__inventory_freeze.sql` 新建冻结审计表，保存冻结前及解冻后的在手/可用/预占快照、操作人、时间、原因及幂等信息。库存记录保存当前冻结编号；唯一约束防止重复活动冻结，数据库约束保证冻结库存可用量为零。冻结不生成虚假的实物数量流水，原收发记录完整保留。

业务统一采用先锁仓库再读写库存的事务顺序。冻结和解冻与预占/扣库互斥，任何持久化失败整体回滚。前端写请求一旦提交即固定内容，失败重试复用原请求；操作期间禁止切仓、翻页及重开弹窗。
