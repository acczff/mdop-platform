## 什么时候需要新 ADR

- 引入新中间件、新框架或跨模块依赖
- 改变事务边界、一致性策略或数据所有权
- 改变分层方式、目录约定或接口风格
- 做出会被后来者质疑“为什么不用另一种方案”的选择

## 写法

背景 → 备选方案 → 决策与理由 → 代价 → 重新评估条件。不写实现细节，不写进度。
