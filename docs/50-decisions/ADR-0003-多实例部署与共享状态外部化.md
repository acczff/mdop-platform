# ADR-0003：多实例部署与共享状态外部化

- 状态：已采纳
- 日期：2026-11-16

## 背景

MDOP 当前为模块化单体，随着业务可用性与零停机发布需求提升，需要支持多后端实例并行部署（前置反向代理或负载均衡器）。原单实例实现中存在进程内状态：Servlet 会话保存在内存、登录失败限流 `LoginThrottle` 使用 `ConcurrentHashMap`、定时投递任务 `DeliveryWorker` 在多实例下会同时轮询 Inbox/Outbox、以及 Flyway 迁移在滚动升级期间可能面临新旧版本混跑。

## 备选方案

1. 粘性会话（Sticky Session）+ 单实例 Worker：减少代码改动，但节点重启仍丢会话、限流在切流后失效，且单点 Worker 故障会中断消息投递。
2. 全面微服务拆分：当前团队与业务规模无需承担跨服务事务、分布式追踪和服务治理成本。
3. 保持模块化单体，外部化共享状态并确保定时任务与数据库迁移并发安全：利用既有 Redis 8.2.7 与 MySQL 8.4.10 消除进程内状态。

## 决策与理由

选择方案 3：

- **外部化会话**：引入 Spring Session + Redis，使任意实例均可校验并延续用户会话，同时保留 `http-only`、`same-site=strict` 与生产 `secure` Cookie 策略。权限或启用状态变更仍通过 `AccountPrincipal.version` 与数据库 `session_version` 校验在 `AccountSessionFilter` 中即时失效会话，并支持按主体索引清理 Redis 会话。
- **分布式登录限流**：抽象 `LoginThrottle` 接口，保留“用户名 + 来源地址”键与固定时间窗口/锁定语义；启用 Redis 时采用 Redis 原子计数与 TTL 过期实现多实例共享限流，未启用 Redis 时回退内存实现以支持轻量单元测试。
- **并发安全的 Outbox/Inbox 投递**：`DeliveryService` 继续使用 MySQL 8.4 `SELECT ... FOR UPDATE SKIP LOCKED` 配合租约字段（`lease_token`、`lease_until`）与 CAS 状态更新，保证多实例 `DeliveryWorker` 并行轮询不会重复认领或重复投递；租约超时后可被其他实例安全接管。
- **定时任务**：幂等/行锁安全的任务（如 `DeliveryWorker`）允许各实例独立调度；未来若新增非幂等全局定时任务（如日结、汇总），再按需引入 ShedLock 或数据库租约锁。
- **滚动升级与迁移纪律**：多实例滚动升级期间新旧版本会短暂共存并连接同一数据库，因此数据库变更必须遵循 Expand/Contract（先扩展兼容、切流后再收缩）原则，禁止在旧版本仍在运行期间删除或重命名旧版本仍在读写的列、表或枚举值。

## 代价

- 运行时强依赖 Redis 可用性：Redis 故障会影响登录与会话校验，需要独立的监控、持久化（AOF）与高可用方案。
- 开发与发布配置需维护 Redis 连接参数与密钥，禁止将默认密码带入生产。
- Expand/Contract 迁移将破坏性表结构清理推迟到后续版本，增加迁移次数与评审纪律要求。

## 重新评估条件

- 业务吞吐或团队边界要求将特定域拆分为独立部署服务。
- 会话或限流需要跨地域多活复制，超出单中心 Redis 拓扑能力。
- 需要严格单实例执行的全局调度任务增多，需要引入统一分布式调度框架。
