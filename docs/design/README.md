# MDOP 界面设计方案

状态：已选定“简洁商务”，采购、销售、生产和库存页面已在现有 Vue 页面中落地并完成本地验收。设计与实现日期：2026-10-12。代码交付状态见[版本与验证记录](../project/status.md)。

## 查看原型

用浏览器打开 [采购订单三版对比](purchase-ui.html)。文件自带样式和演示数据，可离线打开，不需要后端、数据库或 Docker，也不会请求业务接口。

顶栏可切换三种风格，并保留当前订单与详情分区：

| 方向 | 视觉特点 | 适用判断 |
|---|---|---|
| 简洁商务（推荐） | 灰白背景、蓝色主操作、轻边框、适中间距 | 作为全站统一基线，兼顾业务录入与单据阅读 |
| 珍珠玻璃 | 轻透导航、柔和背景、较大圆角；表格保持接近实色 | 适量借鉴材质，避免降低文字对比或增加持续动画 |
| 紧凑专业 | 压缩行间距、缩小页面留白、减少阴影 | 库存台账和高频核对场景；不靠缩小正文字号增加密度 |

三版共用六张演示订单、每页三条。第一张履约中订单提供完整详情及到货安排弹窗。其余记录用于比较不同状态的阅读效果，不代表完整业务流程实现。侧栏为导航分组示意，不执行路由跳转。

可检查：分页、详情返回、详情分区、键盘切换分区、技术标识展开、到货安排数量与必填校验、取消/关闭弹窗、只读账号、列表读取失败、详情读取失败及空列表。到货弹窗的“预览确认”只显示演示反馈，不生成新单据或改变数量。

## 统一设计规则

- 页面结构：当前位置 → 单据标题与状态 → 当前主操作 → 筛选/基本信息 → 表格或详情分区 → 分页/操作记录。列表页不放没有实际统计接口支撑的汇总卡片。
- 标识层级：采购订单号优先；供应商、用途为业务上下文；物料名称与编码配对；内部 ID、版本集中到可展开的技术标识区。不生成新的业务编号。
- 状态语义：蓝色表示执行/选择，绿色表示完成，琥珀表示待审核，红色表示拒绝/错误，灰色表示草稿或只读。始终配有文字，单据状态不替代收货、质检或上架事实。
- 列表密度：默认采用简洁商务，主文本约 13–14px；编码和日期使用等宽字体。表格允许局部横向滚动，手机端不缩小整页。
- 详情布局：顶部概述保持可见；物料与履约、到货安排、操作记录分区展示。状态、权限和未完成事项决定主操作，不展示一排无解释的禁用按钮。
- 基础控件：统一按钮、表格、输入框、提示、状态标签、分页与详情标题。正式落地在现有 Vue 组件中收敛，不同时引入多个 UI 库。
- 异常：列表失败不显示“暂无单据”，详情失败清除旧内容，错误附近提供重试。只读账号不提供写操作入口。正式页面保留原有写入结果待确认、幂等重试与迟到响应隔离机制。
- 响应式：小屏隐藏本原型的示意侧栏；正式应用需提供可打开的移动端导航。内容、按钮和表单换行；长表格仅在表格区域滚动。

## 与当前业务的对应

原型对照 [采购页面](../../frontend/apps/admin/src/views/PurchasingView.vue)、[履约面板](../../frontend/apps/admin/src/components/PurchaseFulfillmentPanel.vue) 及 [数据展示规范](../guides/data-presentation.md)。

- 当前采购订单由已批准需求转单生成；不在订单列表新增“直接建采购订单”入口。
- 当前未建立金额依据；不加入单价、税额、应付、付款和发票数据。
- 第一张演示订单：订单 1,000 千克，安排/净收货 600 千克，尚欠 400 千克，待检 200 千克，累计合格上架 400 千克；冲正、合格待上架、不合格待退、实际退供均为 0。不同单位不汇总。
- 未决事项说明结案不可用的原因。累计上架不代表当前库存，数量结案不代表财务结清。
- 审批保持独立操作人规则；账号按账号展示，不虚构姓名或岗位映射。
- 原型时间明确标注未提供时区；正式界面继续按已有规则区分业务日期、带偏移操作时间与无时区记录。
- 不增加全局搜索、待办统计、价格、跨仓权限、业务状态或接口；原型分页和场景切换仅操作本地示例。

## 采购页落地

实际采购页面采用灰白底色、蓝色主操作、轻边框和文字状态标签。样式通过工作区路由白名单启用，沿用现有控件与权限，不引入新组件库。

- 列表突出单号、用途、供应商、业务日期和状态；保留仓库筛选与服务端分页，不添加无接口依据的统计卡片。
- 查看详情后集中展示单据，按“物料与履约 / 到货安排 / 操作记录”分区。采购需求不展示到货安排分区；返回列表保留筛选、页码、滚动位置并回到原行操作。
- 到货安排入口位于详情主操作区；物料名称、编码、剩余数量和单位共同展示。关联单据、收货记录、审计快照和未完成事项保留。
- 列表与详情分别展示读取失败和重试；读取中返回列表会使迟到响应失效。原有写入结果待确认、原样重试和操作锁定继续生效。
- 390 像素窄屏保留可打开的导航，信息卡片换行，宽表格在自身区域滚动。

本地前端完整检查通过（格式、lint、209 项测试、类型检查及构建）。真实应用浏览器验收覆盖桌面与窄屏、只读与采购账号、分区及键盘切换、返回列表、网络读取失败恢复、到货安排弹窗打开和取消；没有提交业务写入。分页返回与加载中返回后的迟到响应由新增回归测试验证。具体环境与证据见[版本与验证记录](../project/status.md)。

## 销售、生产与库存推广

共用样式位于 [business.css](../../frontend/apps/admin/src/styles/business.css)，仅在以下 13 个路由启用，基础设置及其他收货页面不在本次推广范围。

| 页面组 | 路由 | 展示与交互 |
|---|---|---|
| 采购 | `/purchasing` | 延续已选定的列表、详情和到货安排样式 |
| 销售 | `/sales-orders`、`/sales` | 订单独立详情，物料与履约、发货安排、操作记录分区；出库表格与确认控件复用商务样式 |
| 生产 | `/production-orders`、`/boms`、`/issues`、`/production`、`/finished-goods` | 需求、BOM 和成品集中阅读；固定 BOM、材料与完工执行保留既有分组；接入/事件编号折叠展示 |
| 库存 | `/inventory`、`/transfers`、`/cross-transfers`、`/counts`、`/freezes` | 在手、可用、预占分开；流水保留来源和单位；作业列表、筛选、空态及操作区域统一 |

`RecordTabs` 统一详情分区的 ARIA 关系和键盘操作；`useListPosition` 保留列表滚动与原操作焦点。只处理阅读位置，不改服务端分页、数量算法、权限、审批、写入载荷或幂等恢复。生产执行面板保留原有生命周期，避免切换阅读区域导致表单状态丢失。

推广时前端完整检查通过：35 个文件、215 项测试；PR #46 审查修复库存详情键盘焦点后为 217 项，含格式、lint、类型检查和构建。隔离浏览器验收覆盖桌面、390 像素窄屏、只读展示、分区、列表返回、成品到库存关联跳转，以及销售/生产详情和库存流水失败恢复。仓内移库、跨仓调拨、盘点、冻结在当前验收库的所查范围没有记录，本次浏览器仅验证这些页面的空态、筛选和响应式；有数据的业务操作继续由既有自动回归覆盖，不将空态验收当作过账验收。未提交业务写入。

## 原型验证与后续范围

原型的静态和 DOM 交互检查不等于真实浏览器、接口或业务验收。内置浏览器因禁止 `file://` 协议未能打开本地原型，桌面和窄屏视觉结果尚待人工确认。

已通过 DOM 检查：分页、三版切换保持选中详情、详情分区和键盘切换、结案阻断原因、数量上限/下限与必填校验、演示确认不改变数据、只读操作隐藏、列表/详情失败后重试及空结果区分。原型不加载外部脚本或样式；文档链接与源码索引检查通过。原生弹窗焦点行为和响应式实际渲染未通过浏览器验证。

三版离线原型保留为设计参考；浏览器验收针对真实应用，不将原型模拟交互当作业务验证。后续推广到其他页面时仍需逐页核对字段和操作语义。既有权限、幂等、数量精度、异常恢复和数据快照回归须保留；本轮不扩大业务范围，提交 PR 后等待统一审批，不合并或部署。
