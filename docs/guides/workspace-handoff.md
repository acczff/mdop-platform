# 开发环境交接与换机续接

本页用于交接源码与恢复开发环境。当前功能和历史验收以[项目首页](../../README.md)及[版本记录](../project/status.md)为准，源码已推送不代表数据库、配置和本机资料已备份。

## 离开原环境前

1. 在仓库根目录检查 `git status --short --branch`、`git log -1 --oneline` 与 `git remote -v`，记录交接分支和完整提交 SHA。提交并推送后，用 `git ls-remote origin refs/heads/<分支名>` 核对远端提交。
2. 正式源码、迁移、锁文件、测试及环境模板随 Git 交付。未提交、未跟踪及忽略文件须分别核对；不能用工作区干净推断本机资料已进入远端。
3. 本机 `.env.local`、密码、数据库备份、日志、依赖和临时证据不提交 Git。需要保留的私人设计或验证材料单独移交到受控位置；复制前检查敏感内容，不能把整个工作目录打包公开上传。
4. 需要保留运行数据时，按[发布包手册](../../deploy/release/RUNBOOK.md)确认停写、备份及隔离恢复。Git 不包含 Docker 数据卷，文件复制不能替代数据库一致性备份。本页不授权停服、备份或迁移现有环境。
5. 核对新设备能够访问远端和必要的受控材料，再退出原设备上的 IDE、浏览器及系统账号。账号清理不删除项目源码，也不代替云端会话撤销。

## 在新环境恢复

1. 克隆仓库，检出交接分支或记录的提交；待审分支与已合并主干分开识别。
2. 按[快速开始](quickstart.md)配置工具链和新的本机环境文件。版本以仓库 Wrapper、包管理锁定配置和当前文档为准，不复制旧机器绝对路径或凭据。
3. 明确使用新空库还是已有数据恢复副本。启动会执行迁移，先确认连接目标；数据恢复遵循发布手册，不直接连接未经批准的共享环境。
4. 按[贡献指南](../../CONTRIBUTING.md)执行适用的检查。文档检查、构建、自动化测试、真实业务演练和部署分别记录，旧报告不能代替新环境验证。
5. 按[WMS 演练](wms-walkthrough.md)确认账号、角色、仓库范围和主要流程；新增业务按对应验收文档核对。恢复失败时保留错误证据，不清库或修改历史迁移来绕过问题。

## 交接记录最小内容

| 项目 | 应记录内容 |
|---|---|
| 源码 | 远端、分支、完整 SHA、未合并变更及工作区状态 |
| 本轮验证 | 执行命令、结果、未执行项；历史证据保留原日期 |
| 本机资料 | 哪些不在 Git、是否已受控保存；不在记录中填写密码 |
| 数据与环境 | 是否备份/恢复验证、目标环境、责任人；未做则明确写未做 |
| 下一步 | 当前待办、业务边界、必要授权与验收入口 |

交接完成后仍遵守短分支和 PR 流程，不因换机直接改写主干或删除未确认归属的文件。
