# WMS 业务演练

先完成[工具、账号和仓库初始化](quickstart.md)。以下使用人工创建的模拟资料，不需要导入企业数据。演练结果以实际运行记录为准；本文是可操作步骤，不声称每个新环境已经通过验收。

## 准备一套最小资料

| 资料 | 示例 | 要点 |
|---|---|---|
| 原料仓 | `DEMO-RM` | 启用、原材料用途、实体仓、普通管理 |
| 供应商 | `DEMO-SUP` | 编码唯一 |
| 基本单位 | 空库预置“件”；也可在“基础资料 → 基本单位”新增 | 物料必须选择已登记且启用的单位；不做单位换算 |
| 物料 | `DEMO-MAT`，单位“件” | 批次管理；首次体验可不要求 Date Code/有效期 |
| 待检库位 | `DEMO-QC` | 属于原料仓，区域为待检 |
| 存储库位 | `DEMO-STOCK` | 同仓，区域为存储 |
| 作业员 / 审批员 | 独立账号 | 两人均分配该仓库，作业员演练时另有模拟接口角色 |

这些编码仅供输入示例，仓库、供应商、物料和库位 ID 使用界面实际返回值。重跑时复用资料或使用新编码，外部单号和消息 ID 不要随机变更后当作同一请求重试。

## 主线：100 件采购收货至上架

1. 作业员进入“采购收货”，选择原料仓，使用“本地模拟 ERP 到货”发送 100 件通知，填写新的外部通知号、采购单号及上述资料。
2. 稍后刷新，确认通知到达。此页面使用 RabbitMQ 消息路径；代码中的直接模拟到货接口主要供独立测试使用，两者不能混作同一消息验收。
3. 创建第一份 60 件草稿，填写批次 `DEMO-BATCH-A` 与待检库位。保存后查看库存：草稿不增加库存。
4. 重新打开草稿并提交。通知变为部分收货，待检实存增加 60，可用量为 0；检查收货流水。
5. 创建第二份 40 件草稿并提交。累计 100、全部收货，可用量仍为 0。已提交单据不得通过普通编辑覆盖历史。
6. 在“质检与上架”分别处理两份收货的模拟质检，将合格数量整行上架到存储库位。两份均合格并上架后，这批库存实存合计 100、可用合计 100。
7. 在“库存与追溯”核对余额和流水；在“消息管理”分别核验 Outbox 发布与模拟下游收到，不能只看“已发布”推断外部处理成功。

实际表单字段和状态以页面及[收货/消息契约](../project/I2-I4消息接入与可靠反馈.md)为准。质检来源和整行上架规则见[质检与上架](../project/I7质检与上架.md)。

## 基本异常（使用独立单据）

| 演练 | 预期结果 |
|---|---|
| 超过剩余通知量提交 | 拒绝，余额与流水不多记 |
| 草稿不提交 | 无库存；可继续修改 |
| 超时或连接中断 | 先刷新核对；客户端不自动重发写请求，有幂等键的操作保留原键与原载荷 |
| 无仓库范围账号访问业务 | 后端拒绝越仓，不能靠切换 URL 绕过 |
| 申请人审批自己的单据 | 拒绝；即使之后切换审批角色，仍不能自审 |
| 收货冲正 | 使用未继续下游处理的独立收货单，另一人审批后留下原记录和反向流水 |
| 不合格品退货 | 另建不合格测试单，申请占用额度、另一人审批、仓管确认实际交接才扣库存 |
| 写入成功但列表刷新失败 | 核对已落库事实，不再次创建相同业务 |

不要对已冲正的同一收货单继续上架，也不要为了触发异常直接修改数据库余额。

## 后续三条公共流程

| 流程 | 前置与操作顺序 | 核验重点 |
|---|---|---|
| 生产物料协同 | 合格可用原料、线边仓及库位 → 模拟 MES 需求 → 预占 → 实际发料 → 消耗/余料退回 → 必要时异人冲正 | 发料只转移库位；消耗才减少实存；退料确认实物后记账；工单归属保留 |
| 成品出入库 | 成品仓、待检/存储库位 → 模拟完工 → 待检 → 合格上架 → 模拟销售需求 → 预占 → 拣货 → 另一人复核 → 实物出库 | 未合格上架不可销售；出库与消息反馈分别核验 |
| 库存运营 | 合格库存 → 同仓移库；快照盘点 → 另一人审核；冻结 → 另一人解冻；相同用途仓间申请 → 审批预占 → 整单发出 → 分批实收 | 盘点账变拒绝过账；冻结不抹掉预占；调拨剩余量持续在途，未收齐不完结 |

每个相关仓库都要向参与账号授权；主数据员新建仓库后不会自动扩大旧账号权限。全部通过条件、限制和测试映射见 [WMS 公共流程验收清单](../project/WMS公共流程验收清单.md)。运输短少核销、复杂企业作业策略与真实系统接入暂不启动。
