# 数据展示与业务标识

本规范适用于现有 ERP/WMS 的列表、详情和操作确认。它不增加业务审批步骤，不修改库存过账、数量额度、幂等键或历史结案依据。

## 人能辨识的记录

| 对象 | 展示规则 |
|---|---|
| 物料 | 名称与编码共同展示；批次、单位单独标明 |
| ERP 单据 | 单据类型与原有业务单号，例如销售订单 SO-00000001 |
| WMS 单据 | 中文类型与原有引用，例如销售出库 SO-1、成品入库 FG-2；不重新编号 |
| 完工来源 | 展示现场完工报告号；系统接入需求号保留在来源标识中，两者不能替代 |
| 库存选择 | 物料、库位、批次、可用数量及单位优先；内部记录号仅作末尾区分 |
| 库位 | 展示名称与编码；查询到的当前主数据名称明确标注，不伪造历史名称 |
| 技术记录 | 消息 ID、幂等键等仍保留完整值供排障，不截断后当作唯一业务编号 |

不使用列表行序号替代稳定业务编号。缺少名称时显示“名称未提供”，不通过未授权的接口查询补全，也不将其他字段冒充名称。

## 数量与时间

- 数量显示去掉无意义尾零，保留有效小数与负数；只处理字符串，不通过 JavaScript Number 转换。写入载荷和业务计算保持原格式。
- `0` 与缺失值 `—` 分开。不同物料/单位不相加，不把当前页当作全量；分页总数使用服务端结果。
- 在手、可用、预占、生产占用、在途为不同维度；累计入库量不是当前库存。结案时快照和最新事实分别展示。
- 业务日期使用 `YYYY-MM-DD`，不按浏览器时区换日。成品入库接口将 SQL Date 显式转为日期字符串，覆盖列表和详情。
- 带偏移的操作时间统一显示北京时间并标明。现有无偏移时间按接口原值展示至秒，标明“时区未提供”，不猜测时区或改写历史时间。毫秒/微秒仍保留在接口原值中。

## 页面结构

- 采购、销售、生产、BOM 和成品入库列表使用一致的总数与页码组件，保留原有筛选及服务端分页语义。
- 采购、销售、生产、库存和成品详情使用统一标题、对象与状态区域。
- 生产详情将固定 BOM、完工入库、材料执行与历史分区；工单审批状态不冒充生产完成状态。
- 完工复核意见和确认勾选逐报告独立，操作区域明确报告号、批次及数量；未知写入沿用原重试凭据。
- 成品入库只读详情展示来源、数量、批次、业务日期、收货、质检和上架的操作人及时间。只读账号不获得写权限。
- 完工报告可精确定位成品入库详情，即使目标不在列表当前页。详情仍校验仓库范围。
- 采购来源补充物料与当前库位名称；展示元数据位于履约事实和结案哈希之外，改名不改变核对结果。
- 库存详情突出在手、可用、预占及限制状态；流水列注明单位，保留变动前后及原始关联。
- 读取失败不提示“写入可能成功”；写入超时仍提示结果待确认。新详情加载前清理旧记录，迟到结果不得覆盖当前选择。

## 验收范围与边界

自动化覆盖精度和缺失值、跨日时间、服务端分页、逐报告确认隔离、只读详情、跨仓拒绝、失败后旧详情清除、迟到响应、实际报告号与接入号区分、业务日期和名称变化不影响履约哈希。浏览器按生产完工 → 成品详情 → 库存流水，以及采购/销售详情回查。

现有审计历史的服务端上限仍保留并明确标注；本轮不新建全局搜索服务、待办统计接口、BI 图表、自定义报表或统一编号平台。没有新增数据库迁移，不改写业务快照。发布状态及具体证据见[版本与验证记录](../project/status.md)。
