# 采购 P2：分批到货与 WMS 衔接

范围：PUR-03，依赖采购 P1。100 件订单可安排 60+40，每一安排行持久关联采购订单行及 WMS 通知行。采购不直接记库存，履约归集/结案留 P3。

## 事务和状态设计

- 到货安排为 PENDING（待送达）→ DELIVERED（已送达）或 WITHDRAWN（已撤回）。创建即占用数量；待送达、送达失败和未知结果均不释放额度。安排不可改数量，需撤回后另建。
- 当前同进程同库，通过 common 契约和 integration 适配器调用 WMS；送达和映射确认、撤回和额度释放分别在一个本地事务中提交。没有远程调用或后台消息，不把已有模拟 ERP 入口作为正式链路。跨进程部署须另建可靠投递及确认协议。
- WMS 使用独立来源 `MDOP_PURCHASING`；按安排 ID 和安排行 ID 去重并持久映射，不按物料名称/采购单号猜测。订单的供应商及物料快照保留，新增授权同时检查当前资料有效性。
- 送达失败回滚 WMS 通知和采购映射；另行记录受控失败原因，原安排保留，可查证重试。所有动作携带幂等键、父单版本和原因，响应丢失只能原样重试。
- WMS 撤回先锁到货通知，与创建收货草稿/确认收货使用同一锁。任何收货记录（含草稿、已冲正实收）均阻止撤回；已撤回通知不可新建或提交收货。撤回仅作用于匹配的正式采购来源。
- 正式采购收货与采购撤回统一按“仓库→通知”锁定，避免一方持通知等待仓库、另一方持仓库等待通知的死锁；历史模拟收货入口继续兼容。
- 订单送达后为履约中；全部安排确认撤回且无有效安排时才能取消，随后释放需求占用。采购作业员处理安排，仓管仍按独立收货权限操作；不自动给采购员库存写权限。

## 页面与契约

订单详情展示按行已安排/剩余、安排状态、失败原因、WMS 通知编号/行及收货单引用。采购写权限可创建安排、送达/重试及撤回；有 WMS 查询权限的账号可进入实际通知和收货历史。服务端独立检查权限与仓库范围。

接口在 `/api/v1/purchasing/documents/{id}/arrangements` 创建；`/{arrangementId}/deliver`、`/{arrangementId}/withdraw` 执行动作，返回最新父单详情。采购详情通过契约查询 WMS 引用，不读取其业务表。

## 操作演练

1. 按[快速开始](../guides/quickstart.md)启动相应分支。资料员准备有效供应商、物料、仓库及待检库位；系统管理员为采购作业员、采购审批员、仓管分配该仓库。需要从采购页面进入收货的仓管另配业务只读角色，采购作业员不自动取得收货权限。
2. 采购员创建 100 件需求并提交，另一人批准；采购员转成订单、指定供应商及日期、提交，另一人批准。过程与 [P1](采购P1实现与验收.md)一致。
3. 在订单详情分两次安排 60 和 40，填写预计日期和原因；确认已安排 100、剩余 0。分别点击“送达 WMS”，详情出现稳定通知及行引用。送达失败时查看原因，恢复条件后点“重试送达”；未知结果用“原样重试”。
4. 仓管在采购详情点击“查看 WMS 收货”，或从采购收货列表找到 PA 编号。两次分别登记 60/40，按物料要求填写批次和待检库位，保存再提交；待检库存为 100，可用仍为 0，质检与上架沿用原 WMS 流程。
5. 返回采购订单刷新核对，两份安排各显示实际收货量及收货单引用。订单仍为“履约中”，不是已结案；质量/上架/退供完整归集与结案留 P3。原 WMS 消息反馈机制保留，模拟消费者记录不当作 ERP 履约完成依据。
6. 异常演练用另一份未收货安排：送达后撤回，只有 WMS 确认撤回后剩余额度才恢复。已有收货草稿也不能撤回，不通过删草稿或改库绕过；订单取消必须先满足全部安排撤回条件。

## 验收约束

验收覆盖数量上限、重复/并发不多建通知、权限与旧版本拒绝、失败保留额度并可重试、不可取消存在有效安排的订单、撤回与收货竞争只有一方成功、带草稿/实收不可撤回、旧模拟来源仍可运行。前端验证原样重试及既有迟到结果保护，浏览器完成安排至实际收货。
