# 01 主数据执行规格

适用 R1，生产资料随 R2 补齐。遵循[共同执行约定](README.md)。目标是业务引用可信、历史可解释，不建立独立主数据治理平台。

## 1. 当前基础与责任

规划基线已有供应商、物料、单位文本和库位目录，仓库已有独立聚合、启停与审计。本分支在 [CatalogService](../../backend/mdop-master-data/src/main/java/io/github/acczff/mdop/masterdata/catalog/CatalogService.java) 中补客户、登记单位、单组织及资料受控维护；实现规则与验收边界见[主数据实现与验收](主数据实现与验收.md)。生产 BOM 由生产模块拥有，生产地点 MD-05 的 R2 实现见[生产订单实现与验收](生产订单实现与验收.md)。

## 2. 基本功能工作包

| 编号 | 必做功能与最小资料 | 页面/动作 | 责任与依赖 |
|---|---|---|---|
| MD-01 | 客户、供应商：稳定 ID、唯一编码、名称、状态、版本及审计；说明可选 | 往来单位列表、创建、受控修改、启停、历史 | 资料员维护；客户和供应商身份分别校验，不自动相互转换 |
| MD-02 | 物料/产品：编码、名称、基本单位、现有批次/效期要求及引用状态；产品沿用物料身份 | 物料列表、编辑/启停、历史和被引用提示 | 不复制“ERP 产品表”与“WMS 物料表”；采购/自产库存来源仍由业务决定 |
| MD-03 | 基本单位：编码、名称、状态；为旧单位文本建立明确映射 | 单位查询/维护，物料选用；迁移核对 | 一物料一个基本单位；不加入单位换算。旧文本无法唯一映射时报告待处理，不猜别名 |
| MD-04 | 复用仓库/库位；补单组织的最小工厂标识及资料归属说明 | 使用已有仓库页面；必要组织信息维护、仓库选择 | 当前单组织不是租户隔离。仓库范围授权继续由账号管理负责，不建集团树 |
| MD-05 | R2 所需的生产地点/产线标识及物料生产用途信息 | 最小地点目录，生产订单选择 | 仅补生产订单必填引用，不建工作中心能力、设备台账或工艺路线 |

## 3. 状态、引用和变化规则

资料采用启用/停用和版本保护；启用资料可被新建/审核业务引用。编码一经引用不能改义，已被使用的基本单位和批次策略不能直接切换后重解释旧库存。名称等可维护字段需审计；提交单据保留必要名称/单位快照，历史页面不因当前资料停用而消失。

停用默认阻止新的业务引用和新的授权；已有实物事实的收货、退货、追溯、对账不能统一锁死。对正在执行的订单逐动作核验：原授权内继续执行和安全收尾保留原资料依据，不得新增额度或换物料。涉及安全禁用实物时使用已有库存冻结/质量规则，不把主数据停用当作冻结。

角色：资料员维护，业务人员按已授予目录读取权限引用，系统管理员只分配权限。组织标识是资料语义，不自动扩大用户仓库范围。

## 4. 同编号验收与基本异常

| 编号 | 验收场景与结果 |
|---|---|
| MD-01 | 同编码并发创建只成功一份；旧版本修改冲突；停用客户不能用于新销售单，已交付订单仍可查 |
| MD-02 | 已有收货和库存的物料不允许直接改基本单位/批次语义；改名保留旧单快照；无效物料不生成订单半成品 |
| MD-03 | 旧单位文本逐一映射，数量和原单位含义不变；空值/不明确映射阻断切换，不批量转成默认“件” |
| MD-04 | 越仓选择或新建仓库后未经授权操作均拒绝；仓库停用遵守已有业务限制，组织维护不导致库存串归属 |
| MD-05 | 生产订单可引用有效地点；停用地点不允许新的生产授权，但保留已有工单历史；无用途配置不推断成品种类 |

适用 C-01—C-06；基础资料校验应在提交/审核等关键写入时重做，不能只依赖页面缓存。

## 5. 工厂差异与明确不做

| 差异 | 当前初版 | 取得具体业务后再做 |
|---|---|---|
| 编码和分类 | 稳定内部编码、少量明确字段 | 客户料号、供应商料号、复杂分类/属性模板 |
| 单位与包装 | 单一基本单位 | 箱/件/重量换算、浮动换算、包装层级 |
| 工厂组织 | 单组织、必要地点 | 多法人、跨厂权限、组织树与集团主数据 |
| 品质与追溯 | 复用已有批次和效期要求 | 序列号、Date Code 专有规则、行业属性 |

停止条件：五项按所属轮次通过，可供订单稳定引用；不因字段可能有用而扩表。资料批量导入、供应商评分、客户关系管理均不作为完成门槛。
