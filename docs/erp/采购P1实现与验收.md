# 采购 P1：需求与订单

范围：PUR-01、PUR-02，依赖主数据 PR #34。采购 P2 的到货安排、WMS 授权和 P3 履约结案尚未接入；本工作包没有库存写入，也没有金额依据。

## 状态与职责

- 需求：DRAFT（草稿）→ SUBMITTED（待审核）→ APPROVED（已批准）→ CONVERTED（已转单）。审核可驳回至 REJECTED，草稿/驳回可编辑；未转单可撤销为 CANCELLED。
- 订单：已批准需求整单转成 DRAFT；编辑供应商、到货日期及用途后提交，异人批准或驳回。批准后锁定。P1 尚无下游执行，取消订单与释放需求占用在一个事务内完成；P2 必须增加下游撤回确认门禁后才能接入执行。
- 一份需求一个收货仓、多物料；重复物料合并数量，精度最多六位，数量大于零。转单保持需求行、数量、单位及物料名称快照，不支持拆单/汇单，订单不能改变已经批准的需求数量。
- 仓库在首次建单后固定。采购作业员可维护仓库范围内的单据，审批员只有读取与审核；系统管理员和仓管不自动获得采购写权限。原建单人、最后编辑人及提交人不得审批同一单据，角色变更也不能绕过。
- 草稿引用当前有效目录；提交及审批重新检查仓库、物料、单位和供应商有效性，批准需求时锁定物料策略并刷新授权快照。拒绝、撤销和取消可在资料停用后执行，保留历史快照。

## API、事务与数据

新增 `mdop-purchasing`，仅依赖 common、security、master-data，不依赖或写入 WMS。迁移位于 purchasing 目录，统一由 boot 装配。

`/api/v1/purchasing/documents`：GET 按仓库/类型分页；POST 新建需求；`/{id}` GET 详情、PUT 草稿编辑；`/{id}/actions/{submit|approve|reject|cancel}` POST 状态操作；`/{id}/convert` POST 整单转订单。详情包括行、历史、关联单据，数量输出字符串。

编号使用 `PR-` / `PO-` 加递增单据 ID（至少八位），允许回滚产生断号；业务日期按 `yyyy-MM-dd` 输出，不经过 UTC 时间转换。审批发现提交后基本单位已变化时拒绝，要求驳回并重新核对数量，不静默替换单位。

所有写操作带幂等键，更新/动作带版本，审核/取消带原因。同键同操作者同载荷返回已生成单据的当前状态，同键不同载荷或动作拒绝。仓库锁串行化同仓写入，随后锁定单据；状态/版本检查、行快照、占用与审计及幂等凭据同事务提交。转单竞争仅产生一张有效订单；历史取消订单保留来源，取消成功后需求可重新转单。只读列表和详情先检查仓库权限。

前端写结果不明时保留原请求用于原样重试或查证，不允许换键创建；读失败清除可操作数据，切仓/切单忽略迟到响应。页面沿用已确认的简洁导航与列表，详情集中展示状态、可执行动作、来源与历史。
