# 采购 P3：数量履约与结案

范围：PUR-04/05，依赖 [P1 需求与订单](采购P1实现与验收.md)及 [P2 到货衔接](采购P2实现与验收.md)。这是数量履约候选实现，不代表 PR 已合并、日常数据库已升级或财务结清。提交和实际检查见[版本记录](../project/status.md)。

## 1. 事实来源与模块边界

采购详情通过 `PurchaseReceivingPort.fulfillment` 获取 WMS 收货行、质检、上架、差异/冲正和退供事实，integration 适配到 WMS 查询服务。关联使用订单行→安排行→通知行→收货行的稳定 ID，采购不读写 WMS 业务表、不从当前库存余额倒推履约。

当前正式采购采用同进程、同库查询契约，不新增一套异步反馈累计表。查询基于已提交事实；重复刷新或模拟反馈乱序不改变数量。现有 WMS Outbox 和模拟消费者保留，模拟队列是否发送不作为正式采购已履约或未履约的依据，也不把模拟接口开放给采购员。

详情读取使用同一可重复读事务。结案、正式来源的收货/质检/上架/退供/差异冲正写入都先锁仓库，再锁通知及明细，结案检查和落库处于同一事务。旧模拟来源仍沿用已有流程。未来拆库或跨进程时必须另建可靠投递、去重和乱序归并协议；本版不宣称完成分布式消息验收。

## 2. 数量口径

```text
净收货 = 已提交收货 - 已批准冲正
净收货 = 待检 + 合格待上架 + 已合格上架 + 不合格待实际退供 + 已实际退供
尚欠 = 订单授权 - 净收货
```

- 收货草稿不是已收货，未审核冲正不是冲正完成，退供申请/批准不是实物退供。
- 已上架是累计事实，后续领料、移库或销售不减少采购履约量。
- 退供是原收货的处置结果，不减少净收货，不恢复订单安排额度，不自动建补货单或退款。
- 质检合格/不合格数量必须守恒；通知累计必须与有效收货事实一致；来源映射缺失/重复均阻断。
- 未审核差异/冲正、未完成退供、收货草稿、待检、待上架、待实际退供和少收均列出可定位的未完成事项。差异审批仅处理记录，不凭审批结果生成收货或免除数量责任。

## 3. 结案与后续异常

采购作业员在履约中订单点击“确认履约结案”，填写原因。服务端重查每行授权、净收货及处置结果，并检查父单版本、仓库权限和幂等键；只有全部满足时写入 `pur_closure` 并将订单改为 `CLOSED`。

结案结果分为 `QUALIFIED`（全部合格上架）和 `WITH_RETURNS`（含实际退供），保存操作者、时间、原因、完整来源快照及实物事实摘要。结案不释放原需求占用，不允许重新安排、取消或改数量；不提供强制结案、短交核销或自动重开。

每次读取已结案详情都重查来源。新增待审核差异或实物事实发生变化时显示“结案后事实发生变化，待核对”，保留原快照和审计。原结案不能覆盖重写。误报经 WMS 异人审核驳回，且实物事实与原快照一致时，重新核对可恢复一致标识；驳回/撤销等未改变实物的记录仍可查，但不永久破坏事实摘要。真实实物矛盾持续提示，首版不在采购页提供改库或绕过门禁的“修复”操作。

写响应丢失沿用原请求凭据查证/重试，不能换键反复结案。查询失败清空旧详情，恢复后重新读取；“重新核对”是只读动作，不发布消息或调整库存。

## 4. 操作演练

1. 按 P1/P2 准备 100 件已批准订单，分批安排 60+40 并实际收货。采购详情应显示净收货 100、待检 100，不能结案。
2. 通过现有 QMS 模拟入口登记质量结果，仓管到“质检与上架”执行实际上架。全部合格上架 100 时可确认正常结案。
3. 另一张订单采用 80 合格、20 不合格。80 上架后仍显示 20 待实际退供；仓管申请、另一人批准，采购仍不能结案。
4. 仓管录入交接凭据并确认实际退供 20，再回采购详情点击“重新核对”：净收货 100、合格上架 80、实际退供 20，方可确认“含退供结案”。
5. 展开“来源明细与异常记录”和“原结案快照”核对原通知、收货行、质量单、退供及交接凭据。WMS 作业入口按相应查询权限展示；只有采购权限的账号不能直接写 WMS 库存。
6. 异常演练使用独立测试单：20 件未进下游的收货冲正后，净收货减少 20；沿原通知重新收货。少收、未决差异、源数量不一致均不能结案，不借冲正增加安排额度。

## 5. 验收映射

| 场景 | 证据与预期 |
|---|---|
| A01 全部合格 | `PurchaseFulfillmentTests` 分批收货/上架；隔离订单两批 60+40，浏览器确认全部合格结案 |
| A02 含退供 | 实际退供前结案 409，重复确认退供不多扣；隔离浏览器完成 80 上架/20 申请、异人审批、实际退供与结案 |
| A03 冲正 | 原 20 件冲正、同键重放、净收货为 0；沿原通知收齐后可以结案，原冲正来源保留 |
| A04/A05 门禁与并发 | 少收、待检、待上架、未决差异、待交接均阻断；并发同键结案仅一条结案及审计 |
| A06 结果不确定 | 正式事实通过查询读取，不以模拟消息增量累计；最终通知/收货不一致拒绝，恢复源条件后重查；前端结案响应丢失保留原键/版本/原因 |

| 结案后异常 | 新待审差异使一致标识为假，原快照不变；误报审核驳回且实物未变时恢复一致 |
