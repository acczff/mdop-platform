# 主数据 R1 实现与验收

对应 [MD-01—MD-04](01-主数据.md)，所在分支实现状态以[版本记录](../project/status.md)为准。MD-05 的产线/生产地点随 R2 实施；不提前加入 BOM、客户订单、单位换算、多法人或自定义审批。

## 数据、权限与事务

- 供应商、客户、物料、单位使用稳定 ID、唯一编码、名称、ENABLED/DISABLED 与非负 version。编码创建后不可修改；未提供物理删除接口。修改必须提交原 version 和非空原因，成功递增版本。
- 单位名称采用精确比较，不自动将 kg、KG、千克等合并。新物料选择 unitId；兼容旧 unit 文本参数时，必须精确命中已登记且启用的单位。两者同时传入时以 unitId 为准。
- 物料首次获得到货/领料/完工/销售出库需求授权时锁定单位、追踪方式及日期要求，递增版本。未引用物料允许受控变更；已引用物料只允许改名、启停。内部引用锁属于业务事实，不伪造资料员修改记录。
- 单位一旦被物料引用，其名称不可修改；停用仍可保留历史引用。供应商/物料停用不等于冻结库存。
- 组织最多一条，填写工厂内部编码和名称，不预置真实工厂。全部资料共用此组织语义；组织维护不创建租户、数据分区或仓库权限。
- 读取目录沿用登录后全局目录查询；维护与审计要求 masterdata:write（兼容旧 ROLE_ADMIN）。SYSTEM_ADMIN 只有账号管理权限，不自动获得资料维护权限。已有仓库聚合、库位创建和仓库范围授权继续复用。
- 写入资料与 before/after、原因、操作人、时间审计在同一事务提交。行锁与 version 防止覆盖修改；唯一约束处理并发重复编码。单位引用与停用互斥，首个业务引用与物料编辑互斥。

## 新授权与旧单收尾

| 动作 | 规则 |
|---|---|
| 新到货通知 | 供应商、物料和基本单位均须启用；任一行失败则整个通知及引用锁回滚 |
| 新领料、完工入库、销售出库需求 | 物料及基本单位须启用；相同需求原样重试返回原结果，不因后续停用重新授权 |
| 已有通知收货/提交、质检、退供等收尾 | 按原单数量、状态与既有权限执行，不因为当前资料停用统一阻断 |
| 盘点、冻结、移库等已有库存运营 | 保持原有实物/权限规则；资料停用不代替库存冻结，也不改变已有库存身份 |
| ERP 客户销售单 | 尚未开发。客户目录已提供启用引用检查，后续 SAL 工作包接入；不能把模拟销售 customerReference 文本视为客户主数据外键 |

到货通知保留供应商编码/名称，到货行已有物料编码/名称/单位快照；领料、完工入库、销售出库需求补物料快照。质检与退供候选读取原到货行名称，退供候选及采购收货反馈读取原通知供应商快照。上述来源单据历史展示原名称；库存查询及盘点、冻结、移库等库存作业仍展示当前物料名称，物料 ID、单位及库存事实不变，本轮未向全部库存作业表复制名称列。

## 接口与页面

路径前缀为 /api/master-data，六类资料从 /catalog 基础资料页面维护。

| 接口 | 返回与限制 |
|---|---|
| GET /suppliers、/materials、/customers、/units、/organizations | 数组，每类最多 1000 条，包含启停状态；组织最多一条 |
| POST /suppliers、/customers、/units、/organizations | code、name；201。客户/供应商分别建立身份，不互相转换 |
| POST /materials | code、name、unitId、trackingMode、requireDateCode、requireExpiry；201 |
| PUT /{kind}/{id} | kind 为上述五种；version、name、reason；非组织还须 status；物料须完整提供 unitId、trackingMode、requireDateCode、requireExpiry；200 |
| GET /{kind}/{id}/history | 审计数组按最新在前排序，最多 1000 条；升级前资料不补造历史 |
| GET/POST /locations | 沿用既有接口；新增时选择启用仓库与区域类型。仓库列表由原仓库接口提供 |

页面中编码只读、已引用物料策略只读；所有启停修改填写原因。查询失败清空可操作数据；网络、409、5xx 或响应解析失败后，即使关闭弹窗也必须成功刷新后才能再次维护。写入成功但刷新失败明确显示“已保存”，不自动补发。

列表支持编码/名称与启用状态组合筛选，设置条件后才显示清空入口，切换资料分类时重置条件；组织和库位不显示启停筛选。页脚默认显示已加载数量，有筛选条件时增加匹配数量；达到 1000 条上限时提示可能未包含全部记录，筛选仅作用于已加载数据。只读账号显示“只读”，资料员入口为“新增”“编辑”“变更历史”；引用锁定、单位/组织/库位维护规则与停用影响在对应编辑界面说明。页签支持方向键及 Home/End 切换。导航按业务分组并沿用原权限，每次只展开一组，只有一个可见菜单时直接提供链接；1100px 及以下默认收起，展开时显示导航，选择目标后返回业务内容；单纯开关导航不重建业务组件。

基础资料创建没有额外幂等键：相同编码不会重复创建，超时后先按编码查询核对，不能更换编码重新发送同一份资料。维护采用版本保护，重复旧版本返回冲突。页面仓库选项最多 100 个，与现有目录规模边界一致。

## 迁移与升级

新增 V202610080002 与 V202610080003，不改已有迁移。

1. 旧物料单位按原文本生成 LEGACY-加哈希编码的单位记录，精确相同文本共享单位。已有文本语义不变，不换算数量；新单位人工编码仍限制 32 位。
2. 空库提供“件”基本单位；已有“件”时复用该记录。空白或不可唯一落库的数据由约束阻断，先清查后升级，不能批量填默认单位。
3. 对已有通知、领料、成品、销售和库存引用回填物料锁；对以前未保存快照的列取升级时现有目录值。旧系统没有更早名称记录，因此不宣称恢复了无法获知的历史名称；已存在的到货行快照保持不变。
4. 升级前必须备份，先在副本演练。MySQL DDL 不能整体事务回滚；迁移失败应保留现场并按发布恢复手册处理，不通过修改旧迁移校验和或盲目 repair 跳过。
5. 应用旧版本无法填写新增非空列；本次升级不是新旧应用混跑方案。回退须使用升级前数据库备份和对应应用包，不能只替换 JAR。

- [CatalogTests](../../backend/mdop-boot/src/test/java/io/github/acczff/mdop/CatalogTests.java)：并发唯一性/版本、权限/CSRF、单位引用、物料锁、审计失败回滚、无效通知整单回滚、资料停用后收货收尾、四类需求身份与快照。
- [CatalogMigrationTests](../../backend/mdop-boot/src/test/java/io/github/acczff/mdop/CatalogMigrationTests.java)：从旧迁移版本带数据升级，精确区分 kg/KG、复用同标签、原数量/快照不变、引用锁、禁止空单位、不重复执行迁移。
- [Catalog.spec.ts](../../frontend/apps/admin/src/__tests__/Catalog.spec.ts)：只读权限、锁定字段、版本/原因、未知写入结果禁止绕过、成功写入后的刷新失败、迟到目录/历史响应、单组织限制与单位选择。
- 全量 WMS/IAM 回归用于核对已有授权、异人审核与库存闭环兼容性。具体执行结果和浏览器覆盖在版本记录中列明，不用测试文件存在代替测试通过。

本轮结束条件为 MD-01—MD-04 的基础维护、已有 WMS 兼容与适用异常通过；客户订单端到端校验随 SAL 开发补齐，MD-05 不纳入本轮完成声明。
