# 材料需求与采购建议实现与验收

本轮为 R2 第三个切片 MFG-03，接在[生产订单授权](生产订单实现与验收.md)之后：已批准工单的固定 BOM → 单层理论材料需求 → 可用库存及关联采购核对 → 人工确认缺口 → 正式采购需求草稿。采购仍走既有独立提交、异人审核、转订单、收货及数量结案流程。范围依据[生产与物料计划规格](05-生产与物料计划.md)，不将本切片称作整个 R2 完成。

## 1. 数量与边界

- 每张工单选一个有权限的启用原材料仓；首次计算后固定，不混合多个仓的库存和建议。账号同时需要工单成品仓与供料原材料仓范围。
- 仅已批准且未取消工单可计算或确认，沿用批准时固定 BOM，不自动切换最新版本。组件须仍启用且基本单位与快照一致；资料停用保留旧计算和安全取消能力。
- 理论需求 = 工单产量 × BOM 组件用量 ÷ 基准产量。BigDecimal 精确乘法，除法向上保留六位；超过 DECIMAL(18,6) 上限拒绝整次计算。页面同时展示原始数量与精确舍入增量分数，循环小数不通过浮点数近似再计算。
- 可用参考只汇总所选仓中合格、正式存储区、企业所有、采购来源、未冻结、未过期且可用大于零的库存；预占数量不再可用。读取不预占、不移动库存，多个工单仍可能看到同一可用量，后续真正领料必须由 WMS 再检查。
- 关联采购参考只含本工单材料生成的需求，不汇总全厂在途。需求数量减去来源事实中的已上架和已实际退供量，得到未入库参考；已取消需求或已结案订单不再提供待入库参考。草稿/驳回需求仍是待办意向，不能解释为已批准采购或保证到货。
- 缺口 = max(理论需求 − 可用参考 − 关联采购未入库参考, 0)。例如需料 20、可用 4，建议 16；关联采购 16 已入库 8 后，可用 12、未入库 8，缺口仍为 0，不能重复计入这 8。
- 每工单每材料只保留一条有效采购需求。已有有效采购时，即使出现剩余缺口，也显示“待核对原采购”，不自动追加。生成需求、取消需求或采购状态变化后，其他建议必须重新计算确认。首版不做分批补差、超量采购、包装倍数、损耗率或替代料。
- 确认整条建议生成 REQUEST 草稿，固定工单号、计算行、材料/基本单位、数量、需求日期及来源。来源需求不可改量、换料或改仓；需调整时先安全取消，再重新计算。采购订单仍可按既有规则选供应商和日期，不能改授权数量。
- 有任何有效关联采购需求时不能普通取消工单。先按已有规则撤回安排、安全取消订单和需求，再取消工单及上游需求；已有实物事实不能绕过采购的取消保护。此处只补采购来源保护，正式领退耗/完工的保护留 MFG-04/05 随接入实现。

## 2. 权限、并发和恢复

复用生产计划员 `manufacturing:read/write`；读取须 read，计算和确认须 write，所有写入须 CSRF。计划员只生成未批准草稿，不获得采购提交/审批权。采购审批人不得是该需求的创建人或提交人，切换角色不绕过实际账号检查。

写入按成品仓与供料仓 ID 升序取得排他锁，再取得 BOM 串行锁，重查工单、组件、余额与关联采购。余额受既有仓库锁保护；物料校验持有行锁。库存参考、已关联供给、计算行在同一事务视图下保存。采购模块通过 `ProductionPurchasePort` 管理采购事实，WMS 通过 `MaterialStockReference` 提供只读库存参考，生产不直接改写它们的余额或单据。

每次计算保存递增版本、事实摘要、完整不可变快照及行。确认必须指定当前计算版本和行，重算事实摘要：余额、预占版本、过期日期、采购/履约状态或日期变化即拒绝旧快照；不会按旧建议继续采购。当前快照用于展示，历史版本和操作者可查，历史完整快照保存在数据库，首版无历史版本切换编辑入口。

命令键区分大小写并绑定工单、操作者、动作与载荷；同键重试返回工单当前材料详情。不同键重复确认、同键异载荷/异人、过期版本、错误建议行均冲突。业务、来源、审计和命令同事务提交，失败不留下半条采购需求。采购需求 ID 与计算行双向关联且唯一。

前端发送前按账号及工单保存原请求到 sessionStorage；未知网络/5xx 结果阻止新写入，重挂载后原样重试。4xx 明确拒绝清除旧可操作快照并要求刷新；存储不可写时不发送，凭据损坏时锁定操作。只读账号无写入口，迟到查询不能覆盖新的操作结果。

## 3. 页面、接口和迁移

“生产需求与订单”已批准/取消工单内展开“材料需求与采购建议”。主表只放材料、理论需求、可用库存、关联采购未入库、缺口和采购建议；公式、舍入口径及计算记录折叠。确认采购前单独展示材料和整量，成功后显示需求单号，由采购人员继续办理。采购详情保留生产工单号和计算行来源。

根路径 `/api/v1/manufacturing/orders/{id}/materials`：

| 请求 | 内容 |
|---|---|
| GET 根路径 | 当前计算、行、关联采购、计算版本记录（最多 1000） |
| POST `/calculate` | `idempotencyKey,warehouseId,orderVersion,planVersion,reason`；无计算时 planVersion=0 |
| POST `/confirm` | `idempotencyKey,planVersion,lineId,reason`；数量由服务端计算，不接受客户端覆盖 |

错误沿用 400 字段、403 权限/仓库/CSRF、404 不存在、409 版本/事实/重复/业务状态、503 未知存储结果。

迁移 `202610090011` 增加 `mfg_material_plan/line/command` 三表，并给采购需求增加生产来源外键和约束；升级后共 36 项迁移、79 张表。旧手工需求及采购订单继续保留原来源与重试载荷，不自动将旧模拟数据认领为生产事实。

## 4. 验证记录

本轮测试覆盖 20−4=16、采购草稿来源、异人审核、部分入库不重复计供给、幂等并发、过期库存/版本/权限/CSRF、源需求不可编辑、取消链、1/3 的六位向上舍入、溢出事务回滚及固定供料仓。页面测试覆盖确认前核对、未知结果原样重试、409 清理、只读、余缺口不追加、存储失败及迟到响应。

本机当前 Docker 引擎不可达，首次后端测试在容器初始化阶段停止，不能视为业务回归通过。最终后端、前端、文档与候选包结果以本 PR 对应提交的 CI 为准；隔离升级和真实浏览器验收待引擎恢复后补齐，不改日常数据库、不自动启动或修复 Docker Desktop。

## 5. 停止点与下一步

本轮止于可核对且不重复的采购需求草稿，沿用既有 PUR 下游执行。下一独立闭环为 MFG-04：工单材料授权 → WMS 受控领料/预占 → 发至线边 → 消耗/余料退回，并补执行后取消保护。当前不生成正式领料、不自动采购、不排程、不报工、不做金额或成本结算。
