# BOM 版本实现与验收

本轮交付 R2 的第一个切片：MFG-01 的独立 BOM 维护闭环。流程为草稿创建/编辑 → 发布 → 复制新版本 → 停用并保留历史，供后续生产订单显式引用。它不表示 R2 整体完成；MFG-01 验收中的“老工单继续使用 V1”须在 MFG-02 工单接入时补验，目前验证的是 V1 自身内容不被 V2 覆盖。

后续进展：第二切片已在[生产订单实现与验收](生产订单实现与验收.md)补齐固定工单快照及 V2 不覆盖旧工单 V1 的验证。本文保留首次 BOM 独立交付的范围与证据，不将两轮验收混为一次。

依据为[生产与物料计划规格](05-生产与物料计划.md)。生产地点 MD-05、生产需求/订单、材料展开、采购建议、领退耗与完工关联在后续切片实施，本轮不创建这些业务的空表或占位页面。

## 1. 模型、权限与版本边界

`mdop-manufacturing` 拥有 BOM、组件、审计、幂等记录及发布串行锁；依赖既有主数据、公共能力和安全模块，不写 WMS 数量账。产品与组件都引用 `mdm_material`，不用另建产品目录。

每份 BOM 包含产品身份/名称/基本单位快照、版本标识、基准产量、组件及其基本单位用量、用途说明、状态、发布/停用操作者和时间。数量使用 `DECIMAL(18,6)`，API 输出精确字符串；基准产量和每条组件用量均须大于零，最多 100 个不同组件。产品不能作为自身组件，重复组件拒绝，调用方应先合并数量。

- 产品和版本标识创建后不变；同产品版本标识不区分大小写唯一。标识为 1—32 位英数字、点、下划线或短横线，首位英数字。
- `DRAFT` 可以编辑用量、组件及说明；创建和编辑仅校验启用物料及单位，不提前锁定未授权的物料身份。
- `PUBLISHED` 内容不可修改，不提供反发布、覆盖或删除；发布同时锁定产品和组件的物料计量/追踪身份。停用物料后历史仍可读，新的发布或复制重新校验启用状态。
- `DISABLED` 保留内容、发布记录与停用原因，不恢复为草稿；变更须复制成一个新的草稿。草稿或发布版本均可复制，保存 `copied_from_id`，原版本不变。
- 复制和发布都核对原单位快照。草稿保存后物料单位变更时拒绝操作，要求编辑草稿、重新核对用量后再继续；不能把原数字静默解释为另一单位。

同产品可以保留多个已发布版本，使用方必须显式选择，不自动替换旧版本、不默认取“最新”。本轮不建立工单引用或假定所有工厂只允许一个有效版本。发布立即生效，时间由服务端记录；不加生效日期排程或动态审批。

新增固定角色 `BOM_MAINTAINER`（BOM 资料员），授予 `warehouse:read` 目录读取和 `bom:read/write`。新授予的 `READER` 包含 `bom:read`；已有账号的持久化权限不会自动扩权，需由系统管理员明确授予/更新。BOM 为单组织共享生产资料，不归属某个仓库；BOM 角色不获得仓库操作权或生产订单批准权。系统管理员及旧 `ADMIN` 不能绕过 BOM 权限。资料发布由 BOM 资料员执行，不冒充生产工单的异人审批。

## 2. 循环、事务和失败恢复

单层表示不递归生成下级工单，不表示忽略跨产品的循环。发布将候选组件与全部已发布版本组成产品依赖图，拒绝任何从组件返回当前产品的路径。检查使用所有已发布版本的边集合，采用保守口径：即使某个版本组合可以避开循环，只要当前有效版本集合存在循环仍拒绝；先明确停用冲突旧版再发布。停用不会修改旧内容，后续历史工单须继续持有自己的固定版本快照。

本版所有 BOM 写操作先锁 `mfg_bom_guard` 单行，再按稳定物料 ID 顺序校验/锁定资料；复制校验亦在该事务内。候选发布和有效图读取不会并发越过彼此，避免 A→B、B→A 分别通过后成环。这是单组织小规模资料维护的简单串行方案，不承诺高吞吐多租户图服务。

写入携带请求键，修改/复制/状态动作还带当前乐观版本及原因。键的摘要绑定操作者、动作、目标和原载荷；同键同载荷重放返回原结果版本的当前状态，同键异载荷/异操作者拒绝。业务变更、资料身份锁、审计、请求记录在同一事务内提交，失败不保留半份 BOM。

页面在发送前按账号把原请求写入 sessionStorage；网络断开或 5xx 时阻止另建，保留“原样重试”。明确 4xx 拒绝后清除待定请求并要求刷新；查询失败/迟到响应不恢复旧操作详情。存储不可用时不发送写请求，损坏凭据阻止新操作。未知结果不能改键重复创建版本。

## 3. 页面与接口

入口“生产协同 → BOM 版本”（仅一个可见子项时直接显示该入口），路径 `/boms`。支持产品编码/名称/版本搜索、状态筛选、服务端分页、详情、版本导航、复制来源和变更前后历史。组件和历史保留快照；版本和历史各最多显示 1000 条，物料选择目录最多 1000 条，不把该上限冒充全部记录。

接口根路径 `/api/v1/manufacturing/boms`；所有 GET 要求 `bom:read`，写请求要求 `bom:write` 和 CSRF。BOM 权限不使用旧管理员旁路。

| 请求 | 输入与结果 |
|---|---|
| GET 根路径 | `q`、`status`（空/DRAFT/PUBLISHED/DISABLED）、零基 `page`、`size`（默认 20、最大 100）；返回 items/total/page/size |
| GET `/{id}` | 返回版本、components、同产品 versions、history、复制来源和发布/停用信息 |
| POST 根路径 | `idempotencyKey,productId,versionLabel,baseQuantity,description,components[{materialId,quantity}],reason`；201，新草稿 |
| PUT `/{id}` | 草稿字段加 `version`；不得更换产品/版本标识 |
| POST `/{id}/copy` | `idempotencyKey,version,versionLabel,reason`；201，新草稿，不修改原版本 |
| POST `/{id}/actions/publish` 或 `/disable` | `idempotencyKey,version,reason`；返回版本最新详情 |

非法字段 400、无权限/CSRF 403、引用不存在 404、重码/单位漂移/循环/版本或状态冲突 409、数据库未知结果 503。具体模型见 [BomModels](../../backend/mdop-manufacturing/src/main/java/io/github/acczff/mdop/manufacturing/BomModels.java)。

## 4. 验收与复现

| 项目 | 本轮结果 |
|---|---|
| 版本生命周期 | 浏览器新建每件产品用料 2 的 V1、发布、复制 V2、编辑为 3、发布，再停用 V1；V1 仍为 2，V2 为 3，复制来源/发布人/停用人/历史可查 |
| 输入与引用 | 后端拒绝自引用、重复组件、零用量、超过六位小数、缺失物料、停用物料和单位漂移；无半成品记录，失败发布不锁定原本未锁物料 |
| 循环与并发 | A→B→C 后拒绝 C→A；停用冲突依赖后可发布；并发相反边发布只有一个成功；同键并发创建只返回一个版本 |
| 权限与历史 | 只读不能写、旧管理员不能旁路、CSRF/旧版本/异操作者重试拒绝；发布版与停用版不能编辑，资料改名不覆盖版本快照 |
| 前端恢复 | 7 项组件用例覆盖只读/发布态、精确数量、复制、未知结果跨重挂载重试、拒绝后清旧详情、迟到读和损坏/不可用存储 |
| 本地门禁 | 7 项 `BomTests` 通过，Maven verify 成功；管理端全量 132 项测试、格式/lint/类型/构建通过；最终 CI 结果写入 PR |
| 隔离迁移 | 从 R1 停写备份恢复到新库 `mdop_bom_qa` 后升级 32→33 迁移、66→71 表，原采购/销售三个结案重新核对一致，47 项库存对账均为零 |
| 页面尺寸 | 桌面及 390 像素窄屏实操；表格在区域内横向滚动，页面宽度 390、弹窗 358，无整体横向溢出，控制台无 error |

复现顺序：在隔离环境升级应用，系统管理员分配独立 BOM 资料员与只读账号，资料员准备启用产品及组件；按上面的 V1/V2 流程操作，再用另两个产品建立相反依赖确认发布阻断。日常数据不作为测试夹具，模拟物料不能假充实际企业配方。

本轮未新增 BOM 专用恢复工具，复用既有停写备份/空库恢复流程。空库 33 迁移由 Testcontainers 回归验证，32→33 带数据升级在隔离环境验证。临时日志、数据库备份、凭据和截图保留在忽略目录 `tmp/bom-*`，不纳入 Git。PR 保留待统一审批，不升级日常库、不合并、不启动或重启 Docker Desktop。

## 5. 本轮停止点与后续

BOM 生命周期、必要异常、接口/页面/测试/迁移/文档完成后结束此切片。下一闭环为 MD-05 / MFG-02：必要生产地点、生产需求转订单、固定 BOM 快照、异人审核及安全取消；必须补验 V2 发布后旧工单仍使用 V1。材料展开和采购建议随后按 MFG-03 接入。不得把本轮资料发布称作生产授权，也不据此宣布 R2 完成。

无多层自动展开、替代料、损耗率、联副产品、工艺路线、设备能力、APS、动态审批或企业规则引擎。
