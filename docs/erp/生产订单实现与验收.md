# 生产需求与订单实现与验收

本轮为 R2 的第二个独立切片：MD-05 最小生产地点、MFG-02 的生产授权闭环，并补验 MFG-01 的旧工单固定 BOM。依据 [生产与物料计划规格](05-生产与物料计划.md)，流程为手工依据/已批准销售行 → 生产需求 → 整量工单草稿 → 提交 → 异人批准或驳回 → 未执行安全取消。不是整个 R2 完成，也不把“已批准”显示成生产已完成。

## 1. 基本规则与停止点

- 产品继续引用现有物料。物料被显式选作需求产品，且工单选择匹配产品的已发布 BOM，才构成本轮生产用途依据；不由物料名称、仓库或追踪方式推断可生产，不添加尚无使用方的制造分类字段。
- 生产地点只含稳定编码、名称、启停、版本与审计，复用“基础资料 → 生产地点”。单组织共享，不是设备、工作中心、产能或工艺路线。新授权重新检查启用状态；已批准历史保持地点名称快照，停用不阻止安全取消。
- 目标仓须为账号有权限的启用成品仓。列表、详情、创建、审核和取消均核对该仓权限；全局目录读取不代表仓库授权。
- 手工需求必填稳定来源依据、产品、正计划量、需求日期和用途；同仓同来源依据唯一。销售需求选择本仓已批准/履约中的销售行，产品、整行数量、单位、日期取自服务端来源，客户端不得覆盖；同销售行只能生成一条需求。整行生产是本项目演示选择，由计划员决定是否采用，不计算缺料、不自动扣除已有库存或发货数量，不宣称等于净生产缺口。
- 需求创建后产品、数量、来源和单位不改写。单位身份被引用锁定。需求可取消但不删除、复活或以同来源重复创建；如果只是调整地点/日期/BOM，编辑未批准工单即可；安全取消工单后可从仍有效的原需求重新建单。
- 一条需求整量分配给一张有效工单，草稿也占用需求；数据库唯一约束和事务锁防止不同请求键并发多建。首版不拆分工单、不合并需求，不支持部分授权或超产。
- 工单草稿/驳回状态可修改地点、明确选择的已发布 BOM 和计划日期；不修改需求产品/数量/目标仓。日期仅表示计划，不生成排程；允许晚于需求日期，不假设所有工厂硬性禁止延期。
- 保存工单时即复制完整 BOM 产品、版本、基准产量及组件/单位快照。提交和批准重验所选版本仍发布、地点/产品/组件/单位/仓库有效、销售来源有效；批准后不换版、不改量，新版本或原 BOM 停用均不覆盖旧工单。原始用量与计划产量分别显示，尚不展示未实现的展开需求。
- 审批人不得是需求创建人、工单创建人、最后编辑人或提交人；按实际用户名比较，切换角色也不能自审。驳回必须记录原因，修正后再提交。

当前工单只有 `DRAFT / SUBMITTED / REJECTED / APPROVED / CANCELLED`，没有领料、供给占用或完工入口。因此本轮可取消未执行工单并释放需求；取消需求前须所有工单均已取消。销售取消在同一仓库锁下检查有效生产需求，先取消工单/需求再取消销售源。停用资料不阻断历史读取和这些安全取消动作。

`MFG-` 为 ERP 工单保留编号。旧模拟 MES 领料和成品输入拒绝此编号，防止在受控连接未实现前伪造 ERP 工单执行。已有模拟 WMS 工作流继续使用独立来源编号。升级前应检查自建模拟夹具未占用 `MFG-` 编号段；不将旧同名模拟事实当成 ERP 授权。MFG-04 接入时必须补齐正式来源、供给占用/线边/实物事实检查及撤回确认，并补验“已领料不能普通取消”；本轮没有声称已经完成该执行期验收。

## 2. 权限、事务与恢复

新增 `PRODUCTION_PLANNER`（生产计划员：`manufacturing:read/write`）和 `PRODUCTION_REVIEWER`（生产审批员：`manufacturing:read/review`），均有基础目录、BOM 读取权限，仓库范围单独授予。两个角色不能在同一账号组合。新授予的 `READER` 包含 `manufacturing:read`；旧账号不会被迁移自动扩权。系统管理员/旧 ADMIN 不旁路生产权限。

写入顺序为目标仓库排他锁 → 既有 BOM 串行锁 → 来源/地点/物料校验。销售自己持有来源有效性查询契约 `SalesDemandSource`；生产通过 `ProductionDemandUsage` 向销售提供取消阻断依据，不由销售改写生产表。事务内一并保存业务、版本、审计和幂等记录，失败不留半条需求/工单。BOM 全局锁继续采用适合小规模单组织维护的简单串行方案，不承诺多租户高吞吐。

请求键绑定操作者、动作、目标与完整载荷；同键重试返回原需求的当前状态，同键异载荷/异人冲突。创建工单与取消需求使用需求版本；编辑、提交、审核及取消工单使用工单版本。明确冲突后刷新核对，未知网络/5xx 结果保留原键与载荷，不换键另建。

页面按账号在 sessionStorage 发送前保存原请求；未知结果阻止新操作，支持重挂载后原样重试。明确 4xx 拒绝清理旧操作详情；查询失败/迟到读取不恢复旧可操作单据。存储不可用时不发送写请求，损坏凭据阻止继续写入。无原操作权限时保留待核对记录并提示联系管理员。

## 3. 页面、接口和迁移

入口“生产协同 → 生产需求与订单”，路径 `/production-orders`。按成品仓分页查看需求，详情包含全部最近工单（最多 1000）、固定 BOM、审核信息和操作历史（最多 1000）；基础资料/销售选择/匹配 BOM 最多显示 1000 条。历史取消工单与当前有效工单分别保留，不提供删除。

接口根路径 `/api/v1/manufacturing`：

| 请求 | 语义及主要字段 |
|---|---|
| GET `/demands?warehouseId=&page=&size=` | 本仓分页，需求页从 0 开始，默认 20/最大 100；基础仓库目录沿用从 1 开始的接口 |
| GET `/demands/{id}` | 需求、工单 BOM 快照、审核及历史 |
| GET `/sales-sources?warehouseId=` | 本仓有效销售行选择；最终转单重验 |
| POST `/demands` | `idempotencyKey,warehouseId,sourceType,purpose`；手工加 `sourceReference,productId,quantity,neededDate`，销售只加 `salesLineId` |
| POST `/demands/{id}/orders` | `idempotencyKey,version,siteId,bomId,plannedDate,reason`；整量生成草稿 |
| PUT `/orders/{id}` | 同上，`version` 为工单版本；仅草稿/驳回可修改 |
| POST `/orders/{id}/actions/{submit,approve,reject,cancel}` | `idempotencyKey,version,reason` |
| POST `/demands/{id}/cancel` | `idempotencyKey,version,reason`；无有效工单才可取消 |

GET 要求 `manufacturing:read`；普通写要求 `manufacturing:write`，批准/驳回要求 `manufacturing:review`；全部写要求 CSRF。字段错误 400、权限/越仓/CSRF 403、不存在 404、版本/来源/状态/重复冲突 409、未知存储结果 503。

新增迁移 `202610090009`（主数据生产地点）及 `202610090010`（生产需求、工单、审计、命令），总计 35 项迁移、76 张表。生产工单通过需求持有固定产量及产品依据，`active_demand_id` 唯一约束只在同事务取消时释放；取消不能抹掉原批准信息、BOM 快照及审计。

## 4. 验收证据

| 场景 | 本轮验证 |
|---|---|
| 旧工单 BOM | 后端以 V1 用料 2 建单并独立批准，发布 V2 用料 3、停用 V1 后原工单快照仍为 2；批准工单不可编辑 |
| 正常和取消 | 浏览器手工创建 10 件需求、选演示装配地点及 V2、转单/提交，切换独立审批员批准；隔离 API 销售 10→需求 10→工单→独立批准→取消工单/需求→取消销售源 |
| 重复和并发 | 同键并发返回同一工单，不同键并发只有一个成功；同源重复需求/不同载荷/异人键拒绝；安全取消工单后原需求可重建，历史保留 |
| 授权边界 | 无权限、越仓、自审（含需求创建人/最后编辑人）、CSRF、旧版本拒绝；停用地点/组件/BOM 阻止新授权，驳回和取消仍可收尾 |
| 事务和模拟入口 | 无效数量/精度/地点/不匹配 BOM 无半条工单；模拟领料和成品输入不能以 ERP 编号创建执行事实 |
| 页面恢复 | 7 项组件测试覆盖明确 BOM 选择、销售源取值、已批准不可编辑、原样重试、4xx 清理、迟到响应、损坏/不可用存储；真实浏览器发现仓库起始页不兼容并修复，补严格模拟拒绝第 0 页 |
| 本地门禁 | 8 项生产订单集成测试及 Maven verify 通过；原销售/BOM 21 项在初次兼容回归通过；前端全量 139 项及格式/lint/类型/构建通过，最终全量 CI 写入 PR |
| 升级兼容 | BOM 停写备份恢复到新的 `mdop_production_qa`，33→35 带数据迁移；原采购/销售三个结案重核一致、47 项库存对账无差异，旧 BOM 历史保留 |

浏览器负责手工创建/转单/提交/异人批准和只读、窄屏检查；销售来源、取消链及恢复数据复核由隔离 API 与自动测试负责，不能混称全部浏览器实操。临时账号、截图、日志和数据库备份位于忽略目录 `tmp/production-*`。本地测试复用已运行 Docker 引擎，未启动或重启 Docker Desktop，未升级日常库。PR 保留待统一审批，不自动合并。
