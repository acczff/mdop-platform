# ERP 七个核心部分执行细化

规格基线：2026-10-08 main `f57d616`。这些是执行规格，不是实现或验收完成记录。总体范围以[ERP 总体建设范围](../project/ERP总体建设范围.md)为准；2026-10-09 候选分支的采购、销售数量主线进入 [R1 联合验收](../project/R1采购销售联合验收.md)，实际交付与审批见版本记录。

## 如何区分范围

| 层次 | 执行方式 |
|---|---|
| 基本功能与不变量 | 七份规格中的必做能力及验收项；跨工厂都要保护来源、真实业务事实、数量/金额约束、权限与审计 |
| 本项目初版规则 | 为完成基本闭环选取的明确实现：单组织、固定职责、基本单位、受控数量、手工确认等；写明适用边界，不称为所有工厂的规则 |
| 工厂差异 | 只有取得实际场景、责任人、样例单据和通过条件后才实施；未使用的差异不建配置项、空表或通用规则引擎 |

工厂差异可以改变审批层级、计价或作业方式，但不能取消基本事实约束。例如允许经批准的超收需要新的授权依据，不能直接关闭数量校验。

## 共同执行约定

1. 启动工作包前，核对当前实现及已有测试，只补缺口；先把具体状态、字段、权限、事务和来源事件写入该工作包设计，再加迁移/实现。不要一次创建七套空模块。
2. 每个写操作区分授权数量、计划量和已发生量；库存与凭证等过账事实不可覆盖。草稿可改，提交后按状态限制；未知结果先查证，原请求可原样重试，不换键重建。
3. 数量沿用六位小数。金额、价格精度和舍入在 FIN-01 明确；未启用金额功能时显示“未建立金额依据”，不能默认为 0。业务日期和审计时间沿用现有项目时区约定。
4. 固定职责包括资料维护、采购/销售作业、生产计划、仓库作业、审核、财务录入/复核及只读。按需要扩展现有角色，不要求完整组织权限系统；系统管理员不获得业务操作权限，自审校验比较原操作人而非只看当前角色。
5. 事务保护本模块事实及待发送事件；跨模块用明确契约衔接。需要对方撤回/执行确认才能释放额度时，状态保持待确认，不能因本地发出消息就当作完成。
6. 清单和详情只展示权限范围内的数据，查询失败及迟到响应不保留可操作旧数据；写后刷新失败应显示“操作已保存、刷新失败”或“结果待核对”，不诱导再次创建。
7. 同一工作包包含页面、后端、适用迁移、正常和异常回归、说明及必要浏览器验收。库存等已有工作包以兼容回归为主，不重写已通过实现。
8. 现有模拟数据及消息保留来源；正式应用内 ERP 单据使用独立稳定身份。真实 ERP、MES、QMS 不作为当前开发前置条件，人工和模拟结果须明确标识。

## 共通异常验收

| 编号 | 每个涉及该行为的工作包必须验证 |
|---|---|
| C-01 | 无权限、越仓、自审、账号失效和 CSRF 拒绝，数据不变化 |
| C-02 | 重复提交同键同载荷只产生一份结果；同键异载荷冲突；版本与状态冲突返回可查证依据 |
| C-03 | 并发竞争不超量、不重复过账；事务失败无半条业务、孤立流水或遗漏事件 |
| C-04 | 响应丢失、消息失败/重复/乱序与来源缺失有明确查证、重试或待处理状态，不填造事实 |
| C-05 | 部分执行、下游已有使用或期间已关闭时，不允许普通删除/取消抹掉历史 |
| C-06 | 切单/切仓、迟到响应、列表失败及写后刷新失败不串单、不开放旧操作入口 |

## 依赖与开工顺序

- R1：MD-01—MD-04 的必要部分与 CTL 权限/审计 → PUR-01/02 → PUR-03—05 和 INV 来源衔接 → SAL-01—04 → R1 联合验收。PUR-06、SAL-06 的金额处理留 R3。
- R2：MD-05 → MFG-01—06；通过已有 WMS 操作领退料与完工，按真实缺口扩展 INV；生产生成的采购需求仍进入已有 PUR 审批流程。
- R3：FIN-01 明确初始化、金额与计价口径 → PUR-06/SAL-06 → FIN-02—05；SAL-05 与 INV-04 实物退货联动后验证往来反向处理；FIN-06 成本 → FIN-07 期末核对。存在依赖就串行推进，不空等无关工作。
- R4：复用 CTL 查询和各模块验收，完成总体 G01—G08。采购、生产、销售各一套同源业务数据贯通，不用互不关联的独立演示冒充整体闭环。

## 工厂差异的处理方式

需要差异时记录一条具体决策：工厂/场景、现有流程与证据、与初版不同的规则、影响的功能编号、数据兼容方式、正常/异常验收和责任人。先判断能否用现有明确流程处理；确需改变时只实现这个差异，不猜测其他工厂需求。

已有授权的基本范围继续执行；只在缺少信息会改变业务责任、实物/金额事实或不可逆数据处理时，集中提出具体问题。尤其是财务确认时点、计价成本和税额口径，不能由开发者假定为工厂真实制度；可先用明确标记的演示数据验证程序，未确认口径不得记作真实业务验收完成。

## 完成和停止

工作包以“编号功能、同编号验收、适用 C-01—C-06、页面和文档一致”结束。记录实现提交、测试证据、浏览器覆盖及尚未验证事项；本规格中不预先打勾。完成当轮验收就收口，新增企业差异不追加为当轮结束门槛。代码提交/PR、验收、数据库升级和上线分开记录。
