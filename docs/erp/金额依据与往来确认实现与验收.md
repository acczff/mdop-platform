# R3 首个闭环：金额依据与往来确认

2026-10-12，基于 R2 已合并主干 `316c5aa`。本轮为 FIN-01 必要初始化、PUR-06/SAL-06 正向金额依据及 FIN-02 应收应付确认；不是全部 FIN-01—07 完成，也不是财务结清或生产部署。

## 1. 已确认的演示口径

用户明确选择演示基线：单组织、人民币，金额两位、单价六位、按行四舍五入；财务人工录入依据，关联已确认收发事实，另一人复核后确认应收/应付。不自动计算税额、不回填历史金额、不适用作任意工厂的真实会计政策。

固定政策 `DEMO-CNY-V1`，录入演示组织、启用日及开放期结束日（最多一年），独立财务复核后才开放金额登记。初始化未通过、日期不在开放期间内时拒绝金额确认。初版启用后不能覆盖基线，也不提供任意反关期。最小科目、结算账户、真实期初、存货计价政策随实际使用它们的凭证/收付款/成本切片补齐，本轮不创建占位目录、不声称完整 FIN-01 完成。

- 采购：一条正式 ERP 收货行的**已合格上架数量**作为计价数量；待检、待上架、已冲正或待处理差异不进入正向候选。不合格退供不计入这一正向应付依据。
- 销售：一张正式 ERP 发货安排的**实际出库数量**作为计价数量，同时核对出库状态、原行/物料/仓库、授权数量及流水关联；预占、拣货和复核都不是实际发货。
- 一条收发事实整量计价一次；分批收发形成各自依据，不提供同一收发事实分次计价。可在数量订单尚未全部履约时确认已完成的一批。
- 单价及人工确认金额必须为正，金额必须等于该事实数量乘单价后按行 `HALF_UP` 保留两位；服务端使用 `BigDecimal`，前端提示使用定点整数，不用浮点金额。
- “金额依据号”保存人工参考号，可以关联同一结算依据的不同收发行；去重按方向及来源事实身份，不能只凭客户名称、人工参考号或金额猜同一业务。
- 历史数量单据保持原样，必须显式登记演示金额依据才生成金额记录。没有依据显示未确认，不能补零、把订单量当应付或用当前库存倒推历史。

## 2. 状态、职责与事务

金额依据：草稿 → 提交复核 → 已确认，或待复核 → 驳回；草稿/待复核可受控取消。金额草稿本轮不原地编辑，录错则取消后重建，保留原依据和审计。驳回/取消才释放该来源的有效占用；已确认不能普通取消、删除或覆盖，反向调整由后续 FIN-04 提供。

`FINANCE_OPERATOR` 录入初始化、登记/提交/取消依据；`FINANCE_REVIEWER` 独立复核初始化及往来。两角色不能同账号分配，后端仍按原录入人及提交人拒绝自审，换角色不绕过职责分离。系统管理员、采购员、销售员和仓管不自动获得财务写权限；只读账号按实际仓库范围查询。

金额依据保存订单、订单行、收发事实、往来方和物料快照。提交与复核时重新读取来源；有变化拒绝确认，已确认历史不因来源异常被删除。详情分别显示来源核对和往来核对，后续实物消耗、发出不改变原采购上架事实。

财务事务锁定单组织基线行，串行处理本轮金额命令；唯一有效来源约束和往来记录以依据 ID 为主键共同防止重复确认。状态、往来和审计在同一事务提交；拒绝/异常全部回滚。请求键绑定原操作者、动作、目标及载荷，同键同载荷返回该记录当前状态，不生成第二笔金额。此锁适用于本轮单组织低并发范围，不预建通用工作流或幂等平台。

采购、销售分别实现 `FinanceSourcePort` 只读契约；财务模块不直接写采购、销售或 WMS 表。往来确认不再次增减库存、不生成付款、不投递模拟 ERP 结果。

## 3. 页面与接口

入口：财务往来 → 金额依据与往来。先提交、复核初始化，再选择仓库及应付/应收方向，按完整业务订单号查来源；填写依据号、业务日期、单价、金额和原因后保存草稿，提交另一人复核。列表按仓库、方向、可选原订单号分页，详情展示可读的 `FB-` 依据号、原订单、收发参考、往来方/物料、金额与数量、核对结果和操作历史。

采购/销售订单详情提供财务入口，按原订单查询；财务详情能返回该原订单。页面读取失败清除旧详情，迟到响应/卸载不覆盖当前查询。写前按账号在当前标签页保存完整请求，网络/5xx/认证或超时不确定时保留原请求，禁止新操作；原样重试恢复结果。保存后直接使用响应显示依据，原列表失效后重新读取，不能把旧列表当最新状态。

| 方法 / 路径（前缀 `/api/v1/finance`） | 用途 |
|---|---|
| GET /baseline | 基线状态、版本及历史 |
| POST /baseline | 初始化提交：请求键、版本、组织、起止日期和原因 |
| POST /baseline/approve 或 reject | 独立复核，带版本与原因 |
| GET /sources | `warehouseId`、`direction=PAYABLE\|RECEIVABLE`、完整 `orderNumber` |
| GET /bases | 同仓库/方向，可选订单号；page 从 0 开始，size 默认 20、最大 100 |
| GET /bases/{id} | 依据、往来、来源核对及审计 |
| POST /bases | 来源事实、单价、确认金额、日期、参考号、原因及请求键 |
| POST /bases/{id}/submit、approve、reject、cancel | 状态动作，带请求键、版本和原因 |

本轮确认后未核销金额等于确认金额；草稿/待复核未形成往来，不显示虚假零余额。应收、应付按方向区分，不互相净额抵销。没有收付款、核销、反向调整、凭证/账簿、成本及关期功能，不把“已确认”解释为已结清。
