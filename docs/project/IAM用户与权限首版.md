# IAM 用户与权限首版

本轮唯一成果是可管理的持久化账号、固定角色分配和账号变更审计。WMS 公共业务范围不扩大；组织架构、多租户、SSO、动态审批流、运输短少核销、真实外部系统接入及生产部署不在本轮。

## 账号和初始化

- 账号、密码摘要、启停状态、版本、角色和权限存入 MySQL。账号名称不可修改、不可删除或重新使用，以保持历史操作人与异人审批判断稳定；登录不区分账号大小写，认证身份始终使用数据库原始名称。
- 密码使用 Spring Security 委托编码器的 BCrypt 摘要，至少 12 位且 UTF-8 不超过 72 字节。列表、审计和接口不返回密码或摘要。
- 首次启动由 `mdop.auth.username/password` 创建系统管理员；原 `mdop.auth.operators` 一次性按原权限导入，标记为 `IMPORTED`。完成初始化后，环境变量不再覆盖数据库账号、密码或启停状态，也不会补建新配置账号。新增和重置应在页面操作。
- 初始管理员只拥有 `iam:manage`，不再获得旧 `ROLE_ADMIN` 的全业务权限。升级前确认能访问初始化账号，并准备分别承担系统管理、基础资料、作业、审批和模拟接口职责的账号。
- 原配置导入账号保留现有权限；管理员首次分配固定角色时，原权限由所选角色和仓库范围整体替换。禁止借角色分配增添任意权限字符串。

## 固定角色与仓库范围

| 角色 | 范围 |
|---|---|
| 系统管理员 `SYSTEM_ADMIN` | 用户列表、创建、启停、角色分配、重置密码、账号审计；不能兼任业务角色或分配业务仓库 |
| 基础资料管理员 `MASTER_DATA` | 仓库、供应商、物料、库位维护；基础资料维护为全局权限，不受业务仓库范围限制 |
| 仓库作业员 `WAREHOUSE_OPERATOR` | 现有业务读取、申请、提交、确认、取消等非审批权限；业务数据受仓库范围约束 |
| 业务审批员 `BUSINESS_REVIEWER` | 现有业务读取和审批权限；业务数据受仓库范围约束 |
| 业务只读 `READER` | 现有业务查询；业务数据受仓库范围约束 |
| 模拟接口与消息管理员 `INTEGRATION_OPERATOR` | 现有本地 ERP/MES/QMS 模拟入口及消息管理；需要相应页面时同时分配只读角色和仓库范围，模拟入口仅在 local/test 可用 |

首版提供上述固定模板和分配页面，不提供自定义角色编辑器。分配时保存模板权限快照，未来模板升级不会自动扩大已有账号权限，需重新分配并记录审计。作业与审批角色不能分配给同一账号；业务本身仍检查申请人与审批人不同，即使申请后改为审批角色，也不能审批自己的历史单据。模拟接口属于独立的集成管理权限，不等同于业务审批权限。

仓库范围单独保存为现有 `wms:warehouse:<id>` 权限；仅允许分配存在的仓库。未分配仓库不能访问受限业务数据。基础资料查询保留现有登录用户共享规则。旧 `ROLE_ADMIN` 判断保留用于既有内部测试兼容，正式账号的初始化、导入和分配入口不会授予该角色。

## 并发、会话和异常

- 账号管理写入和审计在同一事务内提交；专用锁行串行化管理变更，保护最后一个启用的系统管理员。界面提交账号版本，过期版本返回 409。
- 不能修改自己的角色或仓库范围；须由另一系统管理员操作。最后一个管理员不能停用或移除管理角色，不通过直接改库解决日常管理问题。
- 停用、重新启用、角色/范围变更、重置密码和本人改密都会递增账号版本。每次已登录请求核对数据库版本及启用状态；旧会话下次请求返回 401，重新启用不能恢复旧会话。已进入执行的业务请求不承诺中途撤销。
- 本人改密必须验证原密码，不能沿用原密码，成功后立即清除当前会话。管理员重置要求原因并使全部原会话失效；初始和重置密码由管理员通过安全渠道告知本人，首版无邮件通知或强制首次改密。
- 账号列表每页 50 条；审计界面展示最近 100 条，数据库保留全部记录。审计含操作人、原因、前后状态及时间，密码变更只记录事件和版本变化。审计时间以带 UTC 时区的时间返回，界面按当前设备时区显示。
- 页面不自动重发写请求。网络失败、版本冲突、服务端 5xx 或无法解析写入响应时，立即作废当前账号列表；关闭弹窗不能解除限制，必须成功刷新后才能再次操作。列表或角色选项读取失败时清空旧数据与分页信息，防止将上一页或旧启停状态当成当前结果。写入成功但刷新失败会明确区分，避免重复创建或重置。密码输入提交后清空。

## 接口与模块

认证和会话校验属于 `mdop-security`，通过 `AccountDirectory` 获取持久化身份；账号管理、初始化和审计属于 `mdop-system`。仓库目录由主数据模块实现公共只读接口，账号服务不直接查询业务表。

| 接口 | 权限/用途 |
|---|---|
| `GET /api/iam/options` | `iam:manage`；固定角色和仓库选项 |
| `GET /api/iam/users?page=0` | `iam:manage`；分页用户列表 |
| `POST /api/iam/users` | `iam:manage`；新增账号 |
| `POST /api/iam/users/{id}/access` | `iam:manage`；版本、角色、仓库范围、原因 |
| `POST /api/iam/users/{id}/status` | `iam:manage`；版本、目标状态、原因 |
| `POST /api/iam/users/{id}/password` | `iam:manage`；版本、新密码、原因 |
| `GET /api/iam/users/{id}/audit` | `iam:manage`；最近 100 条账号变更 |
| `POST /api/auth/password` | 本人已登录；原密码、新密码，成功退出登录 |

全部写接口继续要求 CSRF。页面为 `/users` 和 `/account`，默认进入“我的账号”。管理入口按权限展示，后端独立校验权限。

## 升级、验收和交付

新增迁移 `V202610080001__identity_access.sql`，累计 23 个迁移。升级现有环境前，停止旧版本写入，备份数据库及匹配版本、确认原管理员和操作员配置，再在隔离副本验证初始化与业务权限。更换为前后端配套版本会要求重新登录。升级失败恢复匹配的数据库备份和应用，不能用旧的全权限配置认证继续操作新版本数据库。

回归入口为 `AccountTests`、`AccountWorkflowTests`、`SessionTests` 和 `Users.spec.ts`：覆盖真实登录、越权、角色互斥、仓库范围、重复账号、停用/启用、旧会话失效、角色变更、密码重置、本人改密、CSRF、版本冲突、最后管理员、审计脱敏与改角色后仍不能自审。

2026-10-08 浏览器验收使用独立 MySQL/RabbitMQ、8082 后端和 5174 前端，未连接日常业务数据库：

- 系统管理员只显示账号管理入口；新增只读账号、分配仓库范围成功，最后管理员停用被拒绝。
- 普通账号无法进入用户管理；本人改密立即退出，可用新密码重新登录；后台停用后原浏览器会话下一请求回到登录页。
- 仓管 `iam-worker` 冻结 10 件合格库存，无审批按钮；另一账号 `iam-reviewer` 审批解冻，原单保留两人身份、原因及数量快照。
- 隔离后端重启后 4 个账号及停用状态保留；大写账号登录仍返回原始规范身份，库存保持在手 10、可用 10。47 项库存对账差异均为 0。
- 审计记录包含新增、授权、本人改密和停用；时间使用明确时区，密码及摘要不进入记录。

本地全量执行 186 项后端测试，失败、错误及跳过均为 0；审计时间修复后，`AccountTests`、`AccountWorkflowTests` 和 `SessionTests` 共 12 项针对性 Maven `verify` 再次通过，包括格式、编译与打包检查。前端 `verify` 通过 75 项测试、格式、lint、类型检查及生产构建。PR CI 将对最终提交重新执行完整验收，结果记录在相应 PR；不借用旧提交检查。日常库升级和生产部署另行安排。
