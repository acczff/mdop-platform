# 收货差异与冲正

> 交付更新（2026-10-07）：相关实现已进入 main，WMS 公共流程已完成有限验收，见 [当前验收与合并记录](WMS公共流程验收清单.md)。本文各次测试数量、迁移数量及环境记录保留其当时含义，不代表当前总量或生产部署状态。

## 业务范围

消息迭代已通过PR #12合并。本轮解决正常收货之后的错误纠正，保留原单与历史。差异登记与库存纠正分开：差异审批确认处理意见，不直接修改采购通知数量、不替代QMS质量判定。

| 类型 | 当前处理规则 |
|---|---|
| 短收 | 记录差异及原因，审批确认处理意见，剩余数量继续待收；不自动关闭通知 |
| 超收 | 正常收货继续拒绝超过剩余数量；登记差异后由审批人确认退回或协调意见；审批不授予超收权限 |
| 破损 | 登记数量和说明，记录拒收/异常处理意见；不通过差异登记增加正常库存 |
| 错料 | 必须记录实到物料，通知外物料不进入正常收货；可不关联通知明细 |
| 收货冲正 | 已提交、未冲正、尚未进入检验/上架的整张收货单，申请后由其他人员审批；通过才产生库存影响 |

本轮不实现ERP剩余数量关闭、超收授权、退货单、部分明细冲正、差异导致的自动库存隔离或真实QMS联调。差异数量是业务人员登记的异常数量，不自动从分批到货差额推断。

## 权限与账号

I6 当时除 ADMIN 外，通过 `mdop.auth.operators` 配置有限权限账号，审批与申请/提交权限不能同时授予。该配置式认证已由后续 [IAM 首版](IAM用户与权限首版.md)替代：旧操作员只导入一次，数据库账号、固定角色和用户管理页面已经实现；完整组织权限、SSO 等仍不包含。新环境按[快速开始](../guides/quickstart.md)初始化，不能按旧版 ADMIN 权限理解当前系统管理员。

- 申请：`wms:correction:create`；审批：`wms:correction:approve`；查询：`wms:correction:read`。
- 页面还需 `wms:arrival:read`，并配置目标仓库权限 `wms:warehouse:<id>`；审批/查询/申请都检查目标仓库。
- ADMIN可以承担任一角色，但无论权限高低，申请人始终不能审批自己的单据。
- 本地验收账号 `receiver` 和 `reviewer` 的密码仅保存在被忽略的 `deploy/env/.env.local`，分别为 `MDOP_AUTH_OPERATORS_0_PASSWORD` 和 `MDOP_AUTH_OPERATORS_1_PASSWORD`。本次只授权已有模拟仓库ID=1；不会改变系统Java或其他项目账号。

## 状态与一致性

申请 `PENDING → APPROVED / REJECTED`，带版本与创建/审批幂等键；相同请求重试返回原结果，不同内容或不同操作人复用键被拒绝。同一收货单只允许一条待审批或已通过冲正申请；驳回后可以重新申请。

审批事务按“到货通知 → 申请 → 收货记录 → 按stock_key排序的库存余额”加锁，保持与收货提交一致的锁顺序。通过冲正时：

1. 再次确认收货已提交、未冲正，`downstream_stage=NONE`；待检余额充足且可用量为0。
2. 按原收货流水扣减对应余额，回退到货行累计量；不是将余额覆盖回历史快照，因此其他收货单的数量得到保留。
3. 为每条原流水生成负数流水，唯一关联原流水；原流水和原收货明细不可变。原收货状态继续SUBMITTED，新增 `correction_status=REVERSED` 用于展示。
4. 重新计算到货通知为待收、部分收货或全部收货，增加版本。写入申请审批、操作审计和补偿Outbox。
5. 任一步失败全部回滚。重复审批、并发审批、过期版本、库存不足或下游已开始时，不允许产生第二次影响。

`CorrectionService.markDownstreamStarted` 提供同事务加锁入口，不暴露用户手工修改标记的 HTTP 接口。后续 I7 质量处理已使用该入口保护收货，详见[质检与上架](I7质检与上架.md)；真实 QMS 仍未接入，未来适配必须让真实下游处理与此入口协同，不能只依赖前端按钮。

## 下游补偿

冲正产生 `PurchaseReceiptReversed`（ERP）和 `IncomingInspectionCancelled`（QMS），包含原收货、通知、申请编号、原因、操作人和原事件引用。发布复用Outbox重试/死信机制。

模拟消费者保留每条事件接收记录，并维护收货状态RECEIVED/REVERSED；REVERSED不可被迟到的原收货或检验请求覆盖。模拟接收不代表真实ERP退款/退货，也不代表真实QMS成功撤销检验。真实消费者必须处理重复、乱序及补偿引用。

## 迁移、接口与验收

- `V202610050004__receiving_corrections.sql`：收货冲正/下游标记、允许反向流水的约束、申请与审计表。
- `V202610050005__simulated_corrections.sql`：模拟下游最终状态，兼容已有接收记录。
- `/api/v1/wms/corrections`：按仓库查询最近100条；`/differences`、`/reversals`创建申请；`/{id}/decision`审批；`/{id}/history`审计。
- 前端 `/corrections`：申请、查询、审批和历史；`/receiving`显示已冲正及正反流水；`/messages`显示补偿事件。

验收重点：60+40收货后冲正60，余额剩40且可重新收60；审批人不能自批；跨仓权限拒绝；重复审批和并发审批只冲正一次；检验开始与审批并发最多一方成功；流水写失败时库存、累计量、申请状态和补偿消息全部回滚；补偿后迟到的原事件不恢复下游收货。
