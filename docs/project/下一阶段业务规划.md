# ERP 首轮规划：采购与销售履约

更新日期：2026-10-08。规划基线：main `f57d616`。

用户已确认[ERP 总体建设范围](ERP总体建设范围.md)：主数据、采购、销售、库存、生产与物料计划、财务与成本、查询与控制。**本文只展开 R1 首轮采购/销售数量履约，不能作为 ERP 总体范围或总体完成标准。** 下文“本阶段”均指 R1；生产、财务和基础客户退货已排入后续轮次，并未从总体范围删除。本文不表示新功能已实现，也不授权日常数据库升级或生产部署。

执行清单已细化到[七个核心部分](../erp/README.md)，R1 重点使用 MD、PUR、SAL、INV 和 CTL 工作包；每项有明确功能与验收编号，工厂差异按实际环境另行确定。

### 建设前提：ERP 从零构建

用户已确认目前没有 ERP 系统。本阶段在 MDOP 中从零建设自有 ERP 业务模块，不以现成 ERP、外部订单接口或历史 ERP 数据为前置条件。当前代码中的 ERP_SIMULATOR、模拟到货及模拟反馈仅用于 WMS 演练，不是已经存在的 ERP。

| 从零建设 | 复用现有能力 |
|---|---|
| 采购/销售订单及明细、编号、生命周期、审核与取消、到货/发货安排、履约事实及对账、业务 API 和管理页面 | Java/Vue 工程、数据库迁移、账号会话、权限与审计机制、已有供应商/物料/仓库资料、WMS 库存作业、消息可靠性机制和 CI |
| 客户最小档案、采购/销售业务权限、订单到执行单的稳定关联、各自迁移与回归测试 | 使用现有管理端增加 ERP 导航，不新建独立登录系统、不重复建设库存账 |

从零指 ERP 业务模型和流程从零，不重建整个平台底座。首版仍采用现有模块化单体，由采购、销售模块分别拥有业务事实；不因新增 ERP 而拆微服务或新建独立技术平台。用户通过 ERP 页面直接建单是主入口，模拟接口只保留历史演练用途。

## 1. 一个阶段目标、两条业务主线

首轮目标：由应用内 ERP 订单驱动 WMS 作业，业务单据、执行结果、异常和历史能够连续追溯、核对并按规则结束。

```text
采购：建单 → 审核 → 分批到货安排 → WMS 收货
     → 质检、上架或退供 → 反馈核对 → 采购履约结案

销售：建单 → 审核 → 分批发货安排 → WMS 预占、拣货、复核、出库
     → 实际出库反馈 → 核对 → 销售出库履约结案
```

采购结案不表示已经付款；销售出库履约结案不表示客户已签收、已经回款。首版聚焦数量履约，不宣称完整 ERP 或采购到付款、订单到回款闭环。

## 2. 本阶段模块与职责

| 模块 | 必须交付 | 边界 |
|---|---|---|
| 必要主数据 | 复用供应商、物料、仓库；新增客户最小档案：编码、名称、启停及审计 | 只补两条链路必需字段，不增加完整 CRM、组织树、供应商评价和产品数据平台 |
| ERP 采购 | 手工采购需求及受控转单、采购订单、审核、到货安排、收货及质量/退供结果归集、履约结案 | 转单累计不超有效需求；订单不直接改库存；不建询价、合同、多级采购申请和自动补货 |
| ERP 销售 | 销售订单、审核、发货安排、出库结果归集、未发/已发跟踪和出库履约结案 | 客户属于 ERP 主数据；WMS 中现有 SalesOrder 是出库执行对象，不当成完整 ERP 销售订单 |
| 履约与异常查询 | 各订单内的来源单、执行单、数量、消息状态、阻断原因、历史和对账差异 | 先服务具体采购/销售页面，不另建通用工作流、异常工单平台或 BI 系统 |

职责保持清晰：ERP 管订单及履约事实；WMS 管实物、库存及作业事实；QMS 给出质量判定；MES 给出生产事实。当前 QMS/MES 仍使用已有模拟能力，本阶段不顺带建设其完整系统。

## 3. 公共约束与首版作业选择

必须成立的公共约束：

- 审核、安排和业务事实不能越过上游授权数量；订单、订单行和下游执行行有稳定关联。
- 库存只通过 WMS 已确认的实际作业变更，ERP 不直写库存表、不反推历史履约。
- 收货、质检、上架、退供、实际出库分别记录，不能混用状态或累计数。
- 已发生事实不删除或覆盖；纠正保留原始依据、反向或关联记录、操作者和原因。
- 重复、并发、迟到响应和消息重放不产生第二次业务结果；结果不确定时先查证。
- 权限、仓库范围、职责分离、事务和审计由服务端保证；页面隐藏按钮不是权限校验。

本项目首版建议沿用固定异人审核、单组织、单仓订单、基本计量单位和零超量容差。采购单单供应商、销售单单客户，均可有多物料行；同物料在一张单中合并为一行。不为了未来可能出现的企业差异预建配置引擎。

已经审核的订单不原地改数量、往来方和仓库。尚未执行时按受控取消后重建处理；已经部分执行时保留原单和未履约量，按下面异常边界处理。订单改版、短交结算等复杂处置有实际业务依据后再设计。

## 4. 基本异常必须随主流程交付

| 异常 | 本阶段最低处理 | 不扩展为 |
|---|---|---|
| 输入无效、主数据停用、数量超限、失效状态 | 拒绝并定位到单/行，业务事实与库存不部分写入；历史引用仍能查看 | 动态校验规则引擎 |
| 审核驳回、未执行订单取消 | 原因和审计完整；只在下游已安全撤回、预占已释放且无未决请求时结束取消 | 任意反审核或强制取消 |
| 分批到货/发货、少到/未到、库存不足 | 展示已安排、已执行、剩余和阻断原因，可继续完成余量；不得虚假完结 | 自动采购、自动排程、短交自动核销 |
| 不合格采购收货 | 复用 WMS 退供流程，实际退供后归集；待处置不冒充合格完成 | 退款、赔偿、供应商财务结算 |
| 销售拣货复核不通过、冻结/过期、预占失败 | 复用 WMS 拒绝和重新作业流程；安全取消时释放占用，实际出库后禁止普通取消 | 新建拣货策略、波次、自动配库 |
| 错误收货、已发生业务要求纠正 | 只使用现有合法冲正/退供；没有已确认纠错流程的动作保留事实、原因和阻断提示 | 直接改余额、删流水，或默认扩展客户退货与已出库冲正 |
| 重复、并发、写入响应丢失 | 同一业务只生效一次；保留原请求并查询核对；取消与作业竞争不能双成功 | 全局通用幂等框架重写 |
| 消息失败、重复、乱序、来源关联缺失 | 保留待处理、重试/有权限重放和对账；发布与业务接收分别显示 | 新建企业服务总线 |
| 部分执行后要求变更/提前结案 | 展示已发生事实和剩余责任；不满足规则就阻断，并保留原因，不能用备注代替结案依据 | 订单变更平台、债务豁免或损失核销 |

基本异常的完成标准是“能发现、能定位、能拒绝错误操作，并能按已确认规则恢复”；不要求自动处置所有企业场景。尚未支持的业务处理必须明确显示限制和未完成数量，不能静默失败或伪造成功。

## 5. 与现有 WMS 的最小衔接

- 采购已有采购单号、到货通知及收货/冲正/退供反馈，但没有采购订单本体和完整采购履约订阅。缺口与采购验收见[采购履约实施切片](采购履约实施切片.md)。
- 销售当前入口为[本地模拟销售需求](../../backend/mdop-wms/src/main/java/io/github/acczff/mdop/wms/inventory/LocalSalesController.java)，WMS 支持单物料单批次整单执行。新 ERP 销售订单及每次发货安排需要独立业务身份，不能借用模拟来源冒充正式订单。
- ERP 可按订单行分批安排，分别产生独立 WMS 执行单；首版继续保留单张 WMS 出库单整单、单条库存、单批次的限制。ERP 分批履约不等于为旧 WMS 执行单新增部分发货功能。
- 来源系统、订单 ID/行 ID、安排 ID/行 ID、执行 ID 和业务事件形成稳定映射；不能只按单号或物料猜关联。未发送完、结果未知及撤回未确认的安排仍占用额度，不能提前释放再安排。
- 采购和销售分别拥有本模块的事实与事务。集成适配器负责衔接，使用清晰的调用/消息契约；不跨模块直接改业务表，不通过 `/api/local/*` 建立正式业务。
- 保留旧模拟入口和历史数据兼容，新的 ERP 流程使用独立来源与业务权限。现有消息设施按实际需要复用，不提前抽象一套通用集成平台。

销售行按实际出库事实累计：未发量 = 订单量 - 已确认实际出库量。拣货、复核或预占不计入已发量；仅当所有行未发量为零、所有发货安排有确定结果且反馈对账一致时，允许出库履约结案。已经发出的单据不能通过取消来减少已发量。

## 6. 顺序交付，不同时铺开模块

| 顺序 | 核心成果 | 阶段内结束条件 |
|---|---|---|
| E1 采购闭环 | 从零建立采购模块及订单页面，按采购草案 P1→P2→P3 完成手工需求与转单、订单、WMS 衔接和履约归集 | 不调用模拟 ERP 建单即可完成采购；正常分批收货及不合格退供两条链路通过，转单不超量、不重复，基本异常可验证；此时只完成 ERP 的采购切片 |
| E2 销售闭环 | 客户最小档案、销售订单审核、分批发货安排及 WMS 实际出库反馈 | 一张订单关联多次执行且不超量，正常出库和取消释放通过；出库事实可追溯 |
| E3 首轮联合验收 | 同版本采购/销售演练、异常、权限、消息与数量对账、兼容和恢复验证 | 两条主线及必需异常全部达标，更新文档后结束 R1；随后进入 R2 生产与物料闭环，不视为 ERP 总体完成 |

每个业务切片都包含前端、后端、适用迁移、回归测试、基本异常和使用文档，按 PR 交付。不得把前端和异常留到“全部模块写完以后”；也不为 E2/E3 先创建空模块或占位页面。

## 7. 有限验收与停止条件

| 编号 | 必须验证的结果 |
|---|---|
| ERP-01 | 采购 100 件按 60+40 到货、收货、合格上架，订单至每条执行事实可追溯，完成数量一致 |
| ERP-02 | 采购 80 件合格、20 件不合格：未退供时待处理；实际退供后按明确口径显示含退供结案，不冒充全部合格或已付款 |
| ERP-03 | 销售 100 件按 60+40 安排，各执行单完成预占、拣货、异人复核、实际出库；累计实际出库 100，订单只结束出库履约 |
| ERP-04 | 未执行单安全取消并释放额度/预占；取消与实际执行竞争不双成功；已执行单不能普通取消 |
| ERP-05 | 少交货、库存不足、不合格、冻结/过期和复核驳回有明确剩余量、原因及合法后续动作；受限业务不虚假关闭 |
| ERP-06 | 越权、自审、重复、并发、网络中断、迟到和乱序反馈不多记、不串单、不丢原始事实；关联缺失有待处理记录 |
| ERP-07 | 订单、安排、执行、采购处置及销售出库可对账；发现差异阻止结案，不能依据当前库存余额抹平差异 |
| ERP-08 | 现有四条 WMS 公共流程和历史模拟数据保持兼容；同版本隔离浏览器验收、必要回归、迁移及恢复验证通过 |
| ERP-09 | 新建隔离空库经迁移和必要账号/主数据初始化后，可完全通过 ERP 页面建立采购、销售订单并驱动 WMS；不依赖外部 ERP 或模拟 ERP 建单，QMS/MES 演练输入仍明确标识为模拟 |
| ERP-10 | 手工采购需求审核后可追溯转成采购订单；重复/并发转单不超过有效需求，取消及释放遵循下游未执行条件，不因响应丢失重复占用 |

以上验收满足即结束 R1 首轮交付，不代表 ERP 总体完成；总体结束条件见总体规划 G01—G08。不因发现“还可以加”的功能延后当轮结束。验收中发现缺口，先记录受影响编号、复现证据和最小修复范围；不影响这些条件的事项进入后续需求。代码合并、隔离验收和日常部署分别记录。

## 8. 首轮不做、但总体必做

BOM 及版本、生产订单、基础物料需求与缺料、生产领退料/完工关联进入 R2；基础应收应付、收付款登记与核销、凭证/账簿/期间控制、成本归集及基本客户退货进入 R3。它们不是可无限搁置的可选项，R1 不提前创建空模块或占位实现。

完整财务软件和税务申报、复杂价格策略、询比价合同平台、APS 优化、详细工艺报工、完整 CRM/QMS/IAM、多组织多币种、动态审批与规则引擎、运输短少核销、调拨冲正和真实外部对接仍不在总体范围。首轮延期与总体排除分开表达，具体以[总体边界](ERP总体建设范围.md)为准。
