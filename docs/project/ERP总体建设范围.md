# ERP 总体建设范围与分轮交付

更新日期：2026-10-08。现有代码基线：main `f57d616`。

**用户已确认本总体范围。** MDOP 从零建设自有 ERP，覆盖必要主数据、采购、销售、库存、生产与物料计划、财务与成本、查询与控制。收拢边界是限制各模块深度，不是删去必要模块。本文确认建设范围，不表示这些能力已实现；详细作业和核算口径在对应轮次设计中明确。

七个部分已细化为[执行规格](../erp/README.md)：逐项列出基本功能、初版规则、工厂差异、状态/数据约束、工作包编号、异常与验收场景。执行时先读共同约定再进入对应模块；不能把尚未提出的工厂差异提前实现为配置平台。

## 1. 建设前提与责任

目前没有外部 ERP。现有 ERP_SIMULATOR、模拟到货、模拟销售需求和反馈消费者只用于 WMS 演练，不能充当已经建成的 ERP。新业务由应用内页面建单、审核和执行，不依赖现成 ERP 或历史 ERP 数据。

复用现有 Java/Vue 模块化单体、账号权限、主数据、WMS、消息可靠性机制、迁移和 CI；新建缺少的业务模型、页面、接口、审计和回归。ERP 拥有订单、计划、往来和成本事实，WMS 拥有实物与库存事实；MES 负责详细工序执行，QMS 负责质量判定。生产订单和物料需求属于 ERP 本次范围，不能因 MES 暂未建设而一并排除。

## 2. 总体模块的最小闭环与基本异常

| 模块 | 总体必须覆盖的最小闭环 | 对应基本异常 | 深度边界 |
|---|---|---|---|
| 主数据 | 客户、供应商、物料/产品、基本单位、仓库、必要组织资料；生产轮次补 BOM 及版本；编码、启停、历史引用可追溯 | 重码、无效引用、停用后新业务拒绝、已用资料不可破坏历史 | 单组织起步；不做完整 CRM、供应商评级、集团组织平台 |
| 采购 | 采购需求 → 审核/转单 → 采购订单 → 到货/收货 → 质量与上架/退供 → 履约及应付关联 | 驳回、重复转单、分批/少到、超量、未执行取消、不合格退供、冲正和反馈失败 | 先手工需求，后接物料需求；不做询比价、合同全生命周期、自动寻源 |
| 销售 | 客户订单 → 审核 → 发货安排 → WMS 实际出库 → 履约及应收关联；受控客户退货形成关联反向事实 | 库存不足、分批/超发、复核失败、取消释放、重复反馈、退货超原实际发出量 | 不做商机漏斗、促销、复杂价格折扣、物流运输系统 |
| 库存 | 复用已有收发存、预占、移库/调拨、盘点和追溯；ERP 通过契约获取业务结果 | 负库存、并发抢占、冻结/过期、重复记账、余额与流水差异 | 不建第二套数量库存账；ERP 存货金额核算与 WMS 数量账明确分工 |
| 生产与物料计划 | 销售/手工生产需求 → 生产订单 → 固定 BOM 版本展开 → 基础缺料判断/采购需求 → 领退料/消耗 → 完工与成品入库关联 | BOM 缺失/循环、版本变化、重复展开、缺料、超量、部分执行后取消、完工结果重复或迟到 | 固定版本和一种基础需求计算规则；不做 APS 优化、替代料策略、详细工序派工或完整 MES |
| 财务与成本 | 业务依据 → 应收/应付 → 收付款登记及核销；基础凭证、账簿余额、期间和试算控制；按来源归集存货/生产成本并核对 | 重复确认、超额核销、部分收付款、作废/冲正、跨期或已结期间操作、成本依据缺失/不平 | 单组织、单币种和明确的一种计价/成本口径；不做集团合并、税务申报、银行直连、复杂分摊 |
| 查询与控制 | 单据全链路、权限、审批审计、剩余量/金额、异常原因及对账；查询可回到原始事实 | 无权限、自审、状态冲突、未知写入结果、消息重复/乱序、来源缺失 | 贯穿业务页面，固定流程优先；不单建规则引擎、工作流平台或 BI 平台 |

基础客户退货、应收应付、生产订单和 BOM 是总体必做项；可以分轮交付，不能继续统一标为“未来有需求再说”。完整税务、复杂金融规则和高级生产优化不属于这次基本 ERP 范围。

## 3. 公共约束与企业差异

公共约束在每轮中都必须成立：来源单及行身份稳定、数量/金额精度明确、下游不超过有效授权、状态迁移受控、操作者可查、原始事实不可覆盖；重复与并发不多记、错误不会部分落账、未知结果可查证、事实与消息可对账。

企业差异包括审批层级、超收容差、价格税率、信用额度、计价方法、成本分摊、生产损耗、替代料、短交处置等。设计具体切片时选一个明确可验收的首版口径，不预建覆盖所有企业的可配置机制。不明的金额或成本依据不能用零值、订单数量或当前库存倒推出“真实结果”。

物理完结、业务履约结案和财务结清分别表达；采购收齐不等于全部合格或已付款，实际销售出库不等于客户签收或已回款，生产物料消耗不自动代表成品产量。

## 4. 分轮顺序与结束条件

| 轮次 | 核心成果 | 本轮结束条件 | 不代表 |
|---|---|---|---|
| R1 采购与销售履约 | 必要主数据、采购订单到收货/退供、销售订单到实际出库；补手工采购需求及可追溯转单，主流程及基本异常随切片交付 | 两条数量履约链路可在页面完成，重复/并发/权限/失败恢复及对账通过；既有 WMS 兼容 | 不代表 ERP 总体完成，也不代表已具备财务结算或生产计划 |
| R2 生产与物料闭环 | BOM/版本、生产需求和生产订单、基础展开及缺料、采购需求关联、领退料/消耗及完工入库 | 一笔生产需求能追溯材料需求、采购/库存来源、实际消耗和独立完工事实；缺料、重复、版本和取消异常可控 | 不代表完整 MES、QMS 或 APS |
| R3 基础财务、成本及退货纠正 | 明确金额来源，衔接采购/销售业务依据与应付/应收、部分收付款/核销、基础凭证/账簿及期间控制、成本归集；补关联原销售的客户退货和必要反向处理 | 可分别核对往来未结额、收付款、凭证及业务来源；退货不超原发出量，不重复增库存/冲减往来；成本依据可解释、差异可定位 | 不代表完整财务软件、法定报表合规或真实资金支付 |
| R4 总体验收与收口 | 同版本贯通采购、生产、销售、库存及财务成本，验证基础异常、恢复与文档 | 各模块最小闭环均通过，数量和金额对账无未解释差异，页面可演示、历史可追溯、限制明确 | 不自动启动高级企业策略或生产部署 |

R1 中仍按采购先行、销售随后、联合验收推进，详见[首轮规划](下一阶段业务规划.md)及[采购实施切片](采购履约实施切片.md)。需求/金额等后续轮次字段不提前铺成空表和页面；开发当轮时保护稳定来源身份，并明确新旧数据兼容。

具体工作包及前置关系以[七部分执行顺序](../erp/README.md)为准；主数据和查询控制随业务补齐，不单独排成先造平台的大迭代。财务 FIN-01 的真实确认/计价口径需要具体工厂依据；缺少依据时保留这一明确决策点，其他无关工作继续推进，不能猜测金额事实。

R2 的生产事实可通过明确标识的受控人工确认或现有模拟 MES 结果进入，ERP 仍需持有真实的应用内生产订单及授权数量；不能仅保存一个模拟工单字符串就宣称生产模块完成。成品数量依据完工事实独立记录。

R3 实施前明确金额来源、计价/成本口径、往来确认时点与期间控制。R1/R2 的数量演练数据不自动补成财务历史；以明确的初始化时点和可核验数据建立财务基线。收付款登记是业务记录，不调用银行或代为执行资金交易。

## 5. 总体验收基线

| 编号 | 完成条件 |
|---|---|
| G01 主数据与权限 | 新隔离空库完成迁移、必要资料及角色初始化；页面可以直接发起各模块业务，不依赖外部 ERP 或写库造单 |
| G02 采购 | 需求、订单、分批收货、质量处置、退供及应付依据可关联；重复转单、少到、超量、取消和冲正不会破坏数量/金额事实 |
| G03 生产 | 生产订单固定 BOM 版本，需求、缺料、采购/库存供给、领退料、消耗和完工可追溯；材料与成品按各自事实核对，不隐含推算产量 |
| G04 销售与退货 | 订单、多次出库、未发数量、应收依据可查；客户退货引用原发出记录，实物接收与质量处置、库存和往来调整分别记录 |
| G05 财务与成本 | 部分收付款、核销、反向处理、期间控制可演示；业务依据、往来余额、凭证及成本归集可核对，缺依据时阻断而不填造金额 |
| G06 跨模块闭环 | 使用同一套资料完成销售需求→生产/缺料→采购→材料入库→生产领用与完工→成品出库→往来结清；必要时使用清晰标识的人工/模拟 MES、QMS 输入 |
| G07 基本异常 | 驳回、受控取消、越权/自审、重复/并发、超额、网络中断、迟到/乱序、账实或金额差异均有明确拒绝、查证、恢复或待处理结果 |
| G08 工程交付 | 同版本前后端及必要基础设施回归、隔离浏览器验收、空库与升级/恢复检查通过；设计、运行和限制文档与实现一致 |

各轮达到本轮验收条件就收口；总体达到 G01—G08 才能称“基本 ERP 范围完成”。验收期间只修复破坏既定闭环的缺口，新增能力必须单独说明业务依据、影响和范围，不能持续加成结束门槛。

## 6. 总体仍不包含的内容

完整 CRM、MES、QMS、APS；多租户和集团合并、多币种、复杂单位换算；动态审批/规则引擎；复杂询比价与合同、供应商门户、营销价格策略；复杂成本分摊、税务申报及银行直连；运输短少核销、调拨冲正、运输管理；真实外部系统联调和生产上线。

这些限制不排除上表已明确的基本生产、财务和客户退货功能。特殊环境出现明确需求后，再作为独立范围推进。
