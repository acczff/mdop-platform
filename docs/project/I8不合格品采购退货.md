# 不合格品处置与采购退货

## 已确认的业务规则

2026-10-06 用户确认：先申请，由另一人审批，仓管确认实际退货后才扣库存，并向模拟 ERP 反馈；退款和财务单据不在本轮范围。

本轮处置方式仅支持退回原供应商，不支持仓管直接把不合格品改为合格品，也不包含报废、让步接收、复检、退货区移库或更换供应商。

## 单据与额度

每张退货申请对应一个原收货明细，支持将不合格数量分批申请。状态为待审批 PENDING、待实际退货 APPROVED、驳回 REJECTED、撤销 CANCELLED、已退货 RETURNED。

- 可申请额度 = 原质检不合格数量 - 待审批数量 - 已批准数量 - 已实际退货数量。
- 申请和审批不扣减实物库存、不改变质量状态或可用量。驳回、撤销释放额度。
- 申请人可撤销尚未实际退货的待审批或已批准申请，需填写原因；撤销与实际退货确认互斥。
- 申请人不能审批自己的申请，包括 ADMIN。确认实际退货需要独立操作权限、交接凭证及当前版本；页面要求确认已经实际交接。
- 一次确认扣减此申请的全部数量；需要分批交接时，分别建立申请。
- 实际退货不回退原到货通知累计收货量，不修改原质检结果，也不自动发起补货、退款或冲正。

## 库存、并发与可靠反馈

变更按到货通知、收货单、退货申请、仓库及不合格余额顺序加锁，与现有收货、质检、上架和冲正的锁序兼容。申请核算采用 READ COMMITTED 并加锁读取最新额度记录，避免等待锁后使用旧事务快照产生超额申请。

确认实际退货时，只扣减原 QUALITY_REJECT 流水对应的 REJECTED 余额。生成关联退货申请的 RETURN_OUT 负数流水；原收货、质量和上架流水保留。余额、单据、审计和 Outbox 在同一事务完成，失败全部回滚。

为支持同一收货明细多次退货，新增独立退货流水唯一键；历史单次操作唯一约束继续保留。Outbox 增加 business_key，以退货申请 ID 区分同一收货单的多个 PurchaseReturnConfirmed 事件，既有事件保持空业务键及原去重语义。

模拟 ERP 按退货申请 ID 去重，单独记录 RETURNED 状态，不将整个原收货误标为冲正，也不被迟到的原收货事件覆盖。消息发布复用重试、死信和重放能力。真实 ERP 未接入，模拟反馈不代表退款成功。

## 接口与权限

- `/api/v1/wms/purchase-returns?warehouseId=...`：最近 100 条申请。
- `/candidates?warehouseId=...`：不合格明细、原供应商、位置及可退额度。
- `POST /api/v1/wms/purchase-returns`：申请；`/{id}/decision`：审批；`/{id}/confirm`：实际退货；`/{id}/cancel`：申请人撤销；`/{id}/history`：操作历史。
- 权限：`wms:return:read/create/approve/confirm`；非管理员还需目标 `wms:warehouse:<id>`。配置式审批账号禁止同时授予退货申请或确认权限。
- 请求携带幂等键，状态变更还需当前版本；同键同内容同操作人重试返回现有结果，变更内容或操作人不能复用。
- 前端 `/purchase-returns` 提供申请、跨人员审批、交接确认、撤销和操作历史。ERP 模拟结果在 `/messages` 查询。
