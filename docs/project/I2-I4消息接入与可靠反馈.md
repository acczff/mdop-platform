# 采购收货消息接入与可靠反馈

## 范围与运行

本迭代在现有收货业务上增加真实 RabbitMQ 接入与发布、持久化 Inbox、失败重试、人工重放和 ERP/QMS 模拟接收。本地继续使用 Java 25、后端8081、前端5173，不占用 lc-back 的8080。`local` 配置自动启用消息；其他配置默认 `mdop.messaging.enabled=false`，启用时必须配置 RabbitMQ 连接及目标消费者。

只连接本项目 Compose 的 RabbitMQ。真实 ERP/QMS 账号、网络、外部主数据编码映射、生产授权和业务验收尚未实施。模拟事件使用本项目供应商、仓库和物料ID。模拟消费者接收到检验请求不会放行待检库存。

新增迁移 `V202610050003__reliable_messaging.sql` 扩展已有 Outbox，创建 Inbox、外部单号幂等表、投递日志、模拟接收记录和隔离消息指纹表，不修改历史迁移。已有 PENDING 收货事件在本地启动后会投递至模拟端。

## 消息契约

交换机 `mdop.events.v1`，direct、durable。消息使用 UTF-8 JSON，持久化投递；公共字段：`messageId`（UUID）、`eventType`、`eventVersion=1`、`sourceSystem`、`occurredAt`、`traceId`、`aggregateType`、`aggregateId`、`payload`。

| 事件/路由键 | 来源 | 队列 | 接收行为 |
|---|---|---|---|
| ArrivalNoticeCreated | ERP | mdop.wms.arrivals.v1 | 持久化Inbox，建立到货通知 |
| PurchaseReceiptConfirmed | WMS | mdop.simulator.erp.v1 | 记录模拟ERP收货反馈 |
| IncomingInspectionRequested | WMS | mdop.simulator.qms.v1 | 记录模拟QMS检验请求 |

到货事件 `aggregateType=ArrivalNotice`，`aggregateId` 与 `payload.externalNoticeNo` 一致；payload 为采购订单号、供应商ID、仓库ID、物料及数量明细，最多100行，事件最大256KiB。数量建议使用十进制字符串。重复发送必须保留原消息编号和原业务内容。

`POST /api/local/erp-messages` 接收完整事件并发送到RabbitMQ，202只代表发布已确认；超时可能已经发送，应沿用原编号重试。采购收货页面自动保持同一内容重试时的编号。旧 `/api/local/erp-arrivals` 仅保留给既有本地测试，不用于新消息流程。

## 事务与恢复

1. Rabbit消费者先校验契约，再完整写入Inbox。数据库提交后容器ACK；数据库异常重新投递。无效契约和同编号不同内容进入 `mdop.wms.arrivals.v1.dead` 隔离队列，数据库仅记录指纹、原因及次数，避免在日志暴露载荷。
2. 后台任务用 `FOR UPDATE SKIP LOCKED` 领取任务，60秒租约和随机令牌阻止旧任务覆盖新结果。每2秒处理每个方向最多20条。五次尝试后进入DEAD，重试采用指数退避。
3. Inbox处理事务同时包含外部通知号幂等记录、到货通知与明细、Inbox完成状态及日志。源系统和外部通知号相同且内容一致时返回已有业务；内容不一致进入失败，不能覆盖原单。工作身份仅获得消息目标仓库的数据授权。
4. 收货提交继续原子写入库存、流水和Outbox。发布任务先提交领取事务，再执行网络调用；使用publisher confirm和mandatory return共同判断是否成功。发布失败不会回滚已提交收货。
5. 若broker已接收、应用未记录PUBLISHED就退出，租约过期后会重复发布同一messageId。模拟消费者以消息编号及收货记录/事件类型双重唯一约束去重，模拟结果事务提交后ACK。
6. 只有FAILED/DEAD可人工重放，必须ADMIN、CSRF和原因；保留原消息编号与载荷，重置本轮尝试次数，日志保留历史操作。无效契约隔离消息需在源系统修正后重新发送，不直接重放无效载荷。

## 验收

1. 创建仓库、供应商、物料和待检库位，模拟发送到货事件；查询Inbox为PROCESSED且到货单出现。
2. 保存草稿不改变库存；分批提交后检查通知状态、待检库存、不可变流水，可用量仍为0。
3. 确认每张提交收货单产生ERP反馈和QMS请求，Outbox为PUBLISHED，两个模拟端都有记录。
4. 重复投递相同消息、不同编号相同外部单号，均只建一张到货单；不同内容不能覆盖旧单。
5. 隔离测试环境停止RabbitMQ，确认发送失败；恢复后沿用原消息重新发送。模拟发布后未写完成状态，租约恢复不得重复影响库存或模拟业务结果。
6. 故障注入让到货明细写入失败，确认通知、业务幂等记录与Inbox完成状态一起回滚；修复后重放成功并保留操作记录。
7. 非管理员、缺失CSRF、已成功消息重放必须被拒绝；无效消息隔离后不阻塞下一条合法事件。

运行 `./mdop.cmd verify`，后端使用独立MySQL/RabbitMQ/Redis测试容器，不对本地业务库注入故障。
