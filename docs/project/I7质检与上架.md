# 质检与上架实施范围

## 基线

收货差异与冲正已通过 PR #13 合并到 main，合并提交为 `76534ae`。本迭代从此基线开始，开发分支为 `acczff/quality-putaway`。

## 最小业务闭环

1. 接收模拟 QMS 对整张收货单的质检结果，每条收货明细包含合格数量和不合格数量，两者之和必须等于原收货数量。
2. 质检结果一次性生效，保留原待检流水，生成状态转出和转入流水；总实物库存保持不变。结果生效后禁止原收货整单冲正。
3. 合格库存进入待上架状态，可用数量仍为零；不合格库存保持不可用，暂存原位置并明确显示质量状态。
4. 上架员将每条明细的全部合格数量放入同仓正式存储库位，提交后增加可用数量，保留移出、移入流水和操作人。
5. 重复请求返回原结果；不同内容复用请求键、越权、无效库位、过期物料、库存不足与并发重复处理均拒绝产生第二次库存影响。

## 一致性要求

- 延续到货通知、收货单、库存余额的加锁顺序，与冲正流程互斥。
- 库存唯一维度包含质量状态和位置。通过转出旧余额、转入新余额完成变化，禁止直接修改旧余额的维度。
- 质检结果、上架记录、库存余额和流水在同一数据库事务中完成，任一步失败全部回滚。
- 历史收货数量和到货通知累计量不因质检或上架改变。
- 质量结果模拟入口与正式 WMS 操作区分，并沿用仓库数据权限。

## 暂不包含

真实 QMS 接入、检验方案和抽样过程、复检及结果修改、部分上架、多次拆分上架、不合格品移库或退货、跨仓移库、完整 IAM。

## 验收要求

收货 100 件，质检合格 80 件、不合格 20 件：实物总量始终为 100；质检后可用量为 0；80 件上架后可用量为 80。不合格品不能上架，重复操作不能增加库存。覆盖质量处理与冲正竞争、上架并发、权限拒绝及事务失败回滚。

## 实现与接口

- `V202610060001__quality_putaway.sql` 扩展库存质量状态与流水类型，新增质检结果及上架记录。既有迁移不改写。
- `POST /api/local/qms-results`：仅 local/test 环境、ADMIN 可调用的模拟结果入口。提交收货单版本、外部检验单号、请求键、原因和全部明细数量。本轮为同步请求，不宣称已接入真实 QMS 消息。
- `GET /api/v1/wms/quality?warehouseId=...` 及 `/{receiptId}/items`：查询收货及质检上架记录，需要 ADMIN 或 `wms:quality:read`。
- `POST /api/v1/wms/quality/items/{itemId}/putaway`：整行合格数量上架，需要 ADMIN 或 `wms:putaway:confirm`。非管理员同时需要 `wms:warehouse:<id>`。
- 前端 `/quality` 提供模拟结果、收货明细和上架操作；采购收货页按质量状态展示库存余额。
- 同仓质检与上架串行锁定仓库，以简化当前阶段的跨单库存并发；这是最小实现的吞吐量取舍，后续扩大规模时再评估。
