# I10 仓内移库

> 交付更新（2026-10-07）：相关实现已进入 main，WMS 公共流程已完成有限验收，见 [当前验收与合并记录](WMS公共流程验收清单.md)。本文各次测试数量、迁移数量及环境记录保留其当时含义，不代表当前总量或生产部署状态。

首版支持同仓正式存储库位之间，合格、未过期且可用的库存按数量移动。来源与目标不可相同，不支持跨仓、待检/不合格品移动、质量变更或预占库存移动。

操作人选择来源库存、目标库位、数量并填写原因，实物移动完成后确认。确认生成不可修改的移库单及 TRANSFER_OUT / TRANSFER_IN 成对流水；现有量、可用量同时迁移，仓内总量不变，物料、供应商、批次、Date Code、效期和货权保持一致。首版不引入申请审批或在途库存，误操作通过新移库单反向移回，不删除原单。

库存余额可能汇集多个收货来源，因此移库流水关联移库单和来源/目标库存维度，不伪造单一收货单归属；原收货流水保留。查询沿来源维度可追溯原记录。

所有写入在单个事务中完成，按仓库、库存维度顺序加锁，避免双向移库死锁以及并发超扣。幂等键绑定操作人及请求内容，同键重试返回原单，不重复扣增库存；同键改量或更换人员拒绝。

权限使用 `wms:transfer:read`、`wms:transfer:confirm`，非管理员还需对应仓库范围。已有操作员权限不自动扩大。新迁移增加移库单、流水关联与来源约束；升级前备份，保留历史迁移不改写。

验收覆盖部分移动、多次移库归并、原请求重试、可用量不足、过期/待检/不合格、跨仓/相同库位、越权/CSRF、并发超扣、事务失败回滚、双向流水及库存总量守恒。真实 ERP 联调与跨仓调拨不在本轮范围。

## 接口与页面

- `GET /api/v1/wms/transfers?warehouseId=...&page=0&size=20`：按仓库分页查询已完成单据；`GET /{id}` 查看单据。
- `POST /api/v1/wms/transfers`：来源库存 ID、目标库位、数量、原因和幂等键。返回 TR 编号及来源/目标库存 ID。
- 库存页提供移库操作、实际移动确认与原请求重试；`/transfers` 查看历史单据。
- 移库操作员使用页面需同时具备 `wms:inventory:read`、`wms:transfer:read`、`wms:transfer:confirm` 及仓库范围。配置白名单支持这些权限，但不自动授予现有账号。
- 流水查询兼容无收货单关联的移库记录，提供来源与目标库存跳转。原收货单接口仍只返回属于该收货单的原始业务流水。
- 对账脚本新增移库成对流水和库存维度一致性检查，共 10 项。
