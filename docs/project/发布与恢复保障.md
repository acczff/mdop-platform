# 发布与恢复保障

本轮以用户与权限首版为依赖，只交付可核验的候选发布包、隔离升级与恢复演练、操作手册。不自动合并 PR，不升级日常数据库，不发布生产，不新增 WMS 业务或外部系统接入。

## 完成标准

1. 同一次 CI 的后端、前端检查均通过后，组合其已验证产物，包含实际构建提交、PR 源提交、运行编号、版本、迁移清单及 SHA-256；拒绝混用不同提交或运行的组件。
2. 候选包具备完整性检查命令、外部配置示例和同源反向代理配置。缺文件、额外文件或被修改的文件必须检查失败；校验值不能替代可信来源或审批。
3. 在隔离环境将有业务数据的 22 迁移版本升级为 23 迁移版本，核验 IAM 初始化、已有库存与历史数据及 47 项对账；恢复升级前备份并以匹配旧版应用启动，证明可以恢复。恢复目标只能是空库，不覆盖运行中的数据。
4. 给出操作步骤、停写窗口、失败分支及证据。备份、凭据和原始日志保留在忽略目录，Git 只保存脱敏结论。

## 交付约束

候选包属于可下载的 CI 产物，不等于正式版本发布。PR 检查默认构建 GitHub 的合并候选提交，清单必须同时记录该提交与 PR 源提交，不能将二者混为一谈。主干合并后重新产生主干候选包。

Java 25 运行后端 JAR，前端静态文件通过同源代理访问后端。配置与数据放在包外；校验后的目录不原地修改。首版不引入应用镜像发布、自动部署、TLS/域名申请或集群调度。

备份恢复只演练数据库事实；RabbitMQ 队列和外部系统不回退。恢复副本关闭消息发布与消费，正式事故恢复必须先隔离旧应用并对账已发送事件，避免旧消息重放产生外部副作用。恢复备份会丢弃备份后的变更，不能承诺零数据损失。

## 验证记录

2026-10-08，本地使用 MySQL 8.4.10 独立容器及旧版构建 `0d8e627` 的 JAR，与 IAM `c12c3c1` 的 JAR 演练。旧数据来自此前 WMS 隔离验收备份，不连接日常数据库；本轮不修改业务 Java、数据库迁移或前端业务代码。

| 检查 | 结果 |
|---|---|
| 旧版启动 | 22 个迁移、配置式管理员及原操作员可登录 |
| 22→23 升级 | IAM 迁移成功；管理员变为账号管理专用，旧操作员仓库范围保留 |
| 原业务数据 | 排除新增 IAM 表及新增迁移记录后，全部原业务行的数据指纹与升级前相同 |
| IAM 重启及恢复 | 更改初始化配置不覆盖已有账号；恢复后 3 个账号、停用状态、角色及审计保留，停用账号登录被拒绝 |
| 匹配版本回退 | 升级前备份恢复到另一个空库，旧 JAR 启动并保持 22 个迁移和旧权限模型 |
| 库存守恒 | 升级前、升级后、IAM 恢复后、旧版回退后分别执行 47 项对账，全部差异为 0 |
| 数量复核 | 25 条库存，在手 276、可用 243.876544、预占 0、生产占用 4.123456；回退前后完全一致 |
| 异常阻断 | 不匹配的 JAR、非空恢复目标被拒绝，目标数据不覆盖；损坏包/备份、缺失及额外文件由工具测试验证 |

上述演练 20 个检查通过。发布及备份工具通过 13 项 Node 内置测试；后端与前端既有回归由 PR CI 在最终候选提交重新执行，实际构建提交、可下载包及页面验收记录写入对应 PR，不复用旧提交的检查状态。

本地构建提交 `7166d75` 生成的候选包通过 42 个文件校验并包含 23 个迁移。使用独立 Java 25 和 Nginx 容器加载包内 JAR、静态页面及外部配置，默认关闭消息且不启用 local/test profile；浏览器登录、`/users` 深层刷新、恢复后的账号及停用状态显示通过。健康为 UP，外部 `/actuator/health` 和不存在的静态资源返回 404；`/release.json` 与包清单构建版本一致。最终远端 CI 包的下载校验及复验结果记录在 PR。

本地证据在忽略目录 `tmp/release-rehearsal-20261008025138/`：`result.json`、四份 `*-audit.tsv`、启动日志、两套 SQL 备份及 `snapshot.json`。演练结束后应用进程及本轮数据库容器已停止，保留备份和隔离数据供复核；页面验证单独重启隔离恢复库，由 `tmp/release-web-state.json` 记录对应容器。首次演练的断言把认证框架附加权限也视为业务权限，修正验收断言后完整重跑，不修改业务权限规则。
