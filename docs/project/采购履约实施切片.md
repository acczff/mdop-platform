## 1. 阶段目标与选择依据

本切片先让应用内采购单驱动已有 WMS，完成：

```text
采购员建单 → 另一人审批 → 分批安排到货
→ WMS 分批收货 → 质检 → 合格上架 / 不合格退供
→ 回传事实、核对差异 → 采购履约结案
```

当前没有 ERP 系统。“应用内采购单”是本次从零建立的 MDOP ERP 业务对象，需要新建采购模块、表结构、编号、状态、权限、审批、审计、API 和页面；采购员直接通过页面建单，不依赖外部 ERP 或模拟入口提供订单。复用现有账号、主数据和 WMS，不重建平台底座。QMS 判定继续使用现有模拟入口。阶段终点是数量与处理结果可核对，不是采购到付款闭环。

| 可选方向 | 与当前实现的衔接 | 建议顺序 |
|---|---|---|
| 采购订单履约 | 已有供应商、物料、采购收货、质检、退供和收货反馈，可补齐单据来源及结果归集 | 优先，先完成一个上游系统与 WMS 的纵向闭环 |
| 销售订单履约 | 已有 WMS 销售出库执行，还需客户及订单来源、交付口径 | 本 ERP 阶段第二个业务切片，采购闭环通过后推进 |
| 生产与物料闭环 | 已有线边领料、消耗、退料和成品收货；ERP 生产订单、BOM 与基础需求尚缺 | 已列入 R2；详细工序和完整 MES 仍另行安排 |

总体范围和结束条件以[ERP 总体规划](ERP总体建设范围.md)为准，首轮范围见[R1 规划](下一阶段业务规划.md)；本文只展开采购，不替代总体生产、财务和退货安排。

| 核对对象 | 当前事实 | 新阶段需要补齐 |

## 3. 首版范围和业务口径（建议）

### 公共约束

- 单据有稳定编号、来源行、操作者、时间和审计记录；数量沿用六位小数精度。
- 下游处理不能超过已生效上游授权数量；重复、并发和请求结果不确定时不重复建单或记账。
- 到货安排不改变库存；WMS 实际确认才记库存。采购模块只维护订单和履约视图，不直接更新 WMS 表。
- 收货、质检、上架、退供是不同业务事实；“全部收货”不等于“全部合格”或“履约已结案”。
- 冲正、退供保留原记录，不覆盖历史数量；消息发布成功不等于采购侧已完成处理。

### 本项目首版选择

| 项目 | 建议规则 |
|---|---|
| 采购需求 | 首轮支持手工需求、固定审核及可追溯转单；首版整行转单，不做自动寻源或跨供应商拆分；已转需求不能重复占用，取消订单后仅在下游安全撤回且无未决事实时释放转单额度；R2 再接入物料需求来源 |
| 采购订单 | 一个供应商、一个收货仓库、多物料行；使用现有基本计量单位，不做单位换算 |
| 审核 | 采购员建单、另一人审核；草稿和驳回状态可修改，提交后锁定；审核通过后不直接修改数量或供应商 |
| 权限 | 新增明确的采购作业与审核权限；复用账号和仓库范围，禁止本人审核自己的单据，不授予模拟接口权限代替业务权限 |
| 到货 | 只对已审核订单按行生成分批到货安排；累计有效安排不超过订单量，WMS 按各通知剩余量收货 |
| 撤回 | 未发布草稿可取消；已送达 WMS 的通知仅在无收货草稿、无提交和无下游事实时才可协调撤回，确认后才释放安排额度 |
| 订单取消 | 未发生收货、所有到货安排已确认撤回且无未决消息时才允许取消；与收货竞争必须原子拒绝其中一方 |
| 不合格品 | 继续沿用已确认的申请、异人审批、实物退供确认流程；确认退供前保持待处理 |
| 退供后的补货 | 首版不自动恢复原订单额度；需要补货时另建关联原单的新采购单，保留原单退供结果 |
| 部分未交货 | 原订单保持未结案，明确剩余数量与阻断原因；不伪造收齐，不默认免除供应商剩余责任 |
| 结案 | 各行订单量均有有效收货事实，质检和实物处理均完成，通知及消息无未决差异后可结案；含退供时标明“含退供结案”，不能显示为全部合格交付 |

双人审批、单仓订单、零超收容差、退供另建补货单等是首版作业选择，不是所有企业的统一规则。开始实施前应确认这些选择；本文没有将它们标记为已批准。

订单状态建议为：草稿 → 待审核 → 已审核 → 履约中 → 已结案；驳回回到可编辑状态，符合取消条件时进入已取消。消息投递失败独立展示，不能把订单改为“业务失败”后允许重新建一张相同订单。

### 数量核对

按订单行保存事实明细后汇总，不仅保存可被反复覆盖的累计数：

```text
净收货量 = 已确认收货量 - 已批准收货冲正量
净收货量 = 待检量 + 合格待上架量 + 已合格上架量
         + 不合格未退供量 + 已确认退供量
```

上述分类相互排斥。已合格上架量是累计业务事实，不随后续领料或出库减少；退供申请量不能重复加进净收货量。退供不属于收货冲正，不自动减少通知累计收货或重新开放订单收货额度。

结案要求订单每行净收货量等于订单量、待检/合格待上架/不合格未退供均为零，且所有事实关联可核验。首版不增加“强制结案”按钮绕过这些条件。

## 4. 三个可验收交付项

| 顺序 | 核心成果 | 前后端交付和验收 |
|---|---|---|
| P1 采购需求与订单 | 有来源、可审批、可追溯的需求和采购单 | 手工需求/转单及订单列表、编辑、详情、审批、审计；转单不重复/超量，同供应商同仓多行，主数据、异人审核、版本和状态校验；审核和取消均不改变库存 |
| P2 到货与收货衔接 | 采购单直接驱动 WMS | 分批到货安排、持久化行映射、独立来源、投递及失败查询；从订单进入实际收货单；100 件安排 60+40 并完成两次收货；重复投递不多建通知，撤回与收货并发不释放错误额度 |
| P3 履约闭环 | 收货、质量和退供事实可核对并结案 | 接收收货/冲正/质量/上架/退供事实，采购详情展示履约明细；消息重试及乱序处理、差异列表、阻断原因、结案；完成隔离浏览器验收与对账 |

每项独立包含页面、后端、迁移、回归及文档，通过 PR 交付。P1/P2 是阶段中的可验收切片，只有 P3 完成才称采购履约阶段完成。不把前端和异常处理推迟成未排期的后续工作。

实施时先确定事件/查询契约及模块依赖。可复用现有 Inbox/Outbox 的机制，但不能假定绑定 WMS 表的实现可直接用于采购；应让采购拥有自身事务事实，由集成适配器连接双方，禁止通过本地模拟端点承载正式业务。

## 5. 阶段验收清单

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 100 件订单，60+40 分批到货、收货、全部合格上架 | 一张订单关联所有通知和收货行；结案时合格上架累计 100，消息无差异 |
| A02 | 100 件收货，80 合格上架，20 不合格 | 未退供时不结案；20 件实际退供后显示含退供结案；不自动生成补货或退款 |
| A03 | 未进入下游的 20 件收货被冲正 | 原记录和反向事实均可查；净收货与 WMS 一致，原通知可按既有规则重新收货；不能借机多生成到货额度 |
| A04 | 未到货、少到货或部分收货后请求取消/结案 | 保留实际与剩余数量，拒绝不满足前提的动作，给出可定位的阻断原因 |
| A05 | 重复点击、并发安排、审核冲突、撤回与收货竞争 | 只产生一次有效结果；不超订单/通知额度，不出现部分写入 |
| A06 | 反馈丢失、重复、乱序；写成功后响应丢失 | 按事件与业务身份去重；先收到冲正时不累加错误正向量，关联缺失进入待处理；原请求可查证，不能换键反复记账 |
| A07 | 越仓、无采购权限、自审、停用账号、会话失效 | 前后端按已有边界拒绝，订单与库存不变化 |
| A08 | 升级与历史兼容 | 新迁移只增加结构；原 ERP_SIMULATOR 来源、既有消息及四条 WMS 公共流程仍通过回归；不把历史模拟采购号绑定成新真实订单 |
| A09 | 同版本隔离验收 | 页面完成正常与退供两条闭环；采购订单/到货/收货/质量/退供对账无未解释差异；验证备份恢复，不升级日常库 |
| A10 | 需求审核后转单及并发重试 | 订单行保留需求行来源；同一有效额度仅占用一次；取消释放须满足下游未执行及撤回确认条件，不因响应丢失重复建单 |

消息和查询设计须明确迟到事实如何影响“已结案”。不能丢弃迟到事件或静默覆盖结案快照；发现矛盾时展示待核对并阻止进一步操作，保留原结案审计。

## 6. 暂不纳入的内容和后续顺序

本阶段不做采购申请多级审批、询价比价、合同、价格税额、发票付款、供应商门户、订单变更审批、超收容差、自动补货、短交核销、多组织、多单位换算及真实 ERP 对接。运输短少核销和调拨冲正继续暂缓。

采购切片通过后推进 R1 销售订单履约，再做首轮联合验收。生产订单/BOM 已排入 R2，基础财务成本及客户退货已排入 R3，不是总体范围排除项；本采购切片不提前实现这些模块。完整 IAM、MES、QMS 及高级企业策略仍在总体范围之外。

当前下一步是确认本规划的首版作业选择，然后从 P1 开始详细设计与实施。实现前补全具体 API、数据迁移、事件契约和测试映射；规划期间不提前创建空模块、表或占位页面。
