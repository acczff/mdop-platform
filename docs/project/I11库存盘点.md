# I11 库存盘点

按已确认规则：选择库存生成账面快照，录入实盘数量和差异原因，另一人审核后调整库存并保留流水。审核时库存发生过任何流水变动（即使余额恢复原值）或现有量、可用量变化，拒绝过账，要求取消原单并重新盘点。

首版每单对应一个已有的合格、未过期、正式存储库位库存维度，要求现有量等于可用量，不处理预占库存、待检/不合格库存和发现新的物料/批次。支持零余额维度的盘盈。新批次盘盈、批量盘点和冻结盘点另行迭代。

状态：DRAFT（待录入）→ PENDING（待审核）→ APPROVED（已过账）；创建人可取消 DRAFT/PENDING，其他审核人可驳回 PENDING。提交后数量与原因不可修改；审核、取消和驳回互斥。审核人不得是创建人，即使为管理员。无差异盘点也记录审核结果，但不生成零数量流水。

创建保存账面数量、可用数量和最新流水 ID；过账在仓库锁、盘点单锁、库存锁保护的同一事务内进行。创建键绑定人员与库存维度，提交同内容及审批重试不重复记账。盘盈/盘亏分别使用 COUNT_GAIN/COUNT_LOSS，关联盘点单而非伪造收货来源，不回写采购收货量或发送 ERP 收货消息。

权限：wms:count:read/create/submit/review/cancel，均受仓库范围限制；页面选择库存还需 wms:inventory:read。既有账号不自动扩大权限。升级新增迁移，不改历史迁移；执行本地数据库升级前备份。

本迭代基于移库 PR #17，后续 PR 应以该依赖为基准，待其合并后再切换 main。验收完成前不标记为完整仓储闭环。

## 接口与升级

- GET `/api/v1/wms/counts` 按仓库分页查询，页码从 0 开始。
- POST `/api/v1/wms/counts` 接收 balanceId、idempotencyKey，生成快照。
- POST `/{id}/submit` 接收 quantity、reason；`/{id}/approve` 审核过账；`/{id}/reject`、`/{id}/cancel` 接收处理原因。
- `/counts` 提供盘点记录与操作；从库存页面的“盘点”入口选定来源。只读、录入、审核分别受权限与创建人规则控制。
- `V202610070001__inventory_counts.sql` 新增盘点单和流水关联，继续保留收货、退货和移库约束；对账脚本增加盘点流水和审核一致性检查，共 12 项。
- 本地升级前备份：忽略目录中的 `tmp/mdop-before-counts-20261007.sql`。既有账号权限不自动变化；验收账号仅在隔离运行中配置。
